ALG-U1-Q01MCQeasy

Consider f(n) = 3n² + 5n log n + 7. Which of the following is TRUE?

  1. f(n) = Θ(n²)
  2. f(n) = Θ(n log n)
  3. f(n) = Θ(n³)
  4. f(n) = Θ(n)
Show answer & solution

Detailed solution

Concept. Growth of a sum is governed by its fastest-growing term (the dominant term).

Step by step.

  1. The three terms grow as n², n log n and a constant.
  2. n log n = o(n²), because (n log n)/n² = (log n)/n → 0.
  3. So f(n) is squeezed between 3n² and (3+ε)n² for large n.
  4. Hence f(n) = Θ(n²).

Answer: Θ(n²) — option A.

Common misconception. Adding a lower-order term such as 5n log n never changes the Θ-class. Students who sum the exponents or pick the largest coefficient by eye get B or C.

ALG-U1-Q02MCQeasy

If f(n) = Θ(g(n)) and g(n) = Θ(h(n)), which statement is necessarily TRUE?

  1. f(n) = Θ(h(n))
  2. f(n) = O(h(n)) but f(n) ≠ Θ(h(n))
  3. f(n) = o(h(n))
  4. Nothing can be concluded about f and h
Show answer & solution

Detailed solution

Concept. Θ is an equivalence relation: it is reflexive, symmetric and transitive.

Step by step.

  1. f = Θ(g) gives constants c₁, c₂, n₀ with c₁g(n) ≤ f(n) ≤ c₂g(n) for n ≥ n₀.
  2. g = Θ(h) gives d₁h(n) ≤ g(n) ≤ d₂h(n) for n ≥ n₁.
  3. Chain them for n ≥ max(n₀, n₁): c₁d₁h(n) ≤ f(n) ≤ c₂d₂h(n).
  4. That is exactly f(n) = Θ(h(n)).

Answer: f(n) = Θ(h(n)) — option A.

Common misconception. f = o(h) is strictly stronger than f = Θ(h) and does not follow. Θ gives a two-sided constant-factor sandwich, so it can never collapse to a little-o relation.

ALG-U1-Q03MCQmedium

Which is the correct increasing order of growth (slowest first) for large n?

  1. log log n < log n < √n < n/log n < n
  2. log n < log log n < √n < n < n/log n
  3. log log n < √n < log n < n/log n < n
  4. log log n < log n < n/log n < √n < n
Show answer & solution

Detailed solution

Concept. Compare functions by taking ratios (or logs of both sides) as n → ∞.

Step by step.

  1. log log n = o(log n): log log n / log n → 0.
  2. log n = o(√n): with n = 2^m, m / 2^(m/2) → 0.
  3. √n = o(n/log n): (n/log n)/√n = √n / log n → ∞.
  4. n/log n = o(n) since 1/log n → 0.
  5. Chaining gives log log n < log n < √n < n/log n < n.

Answer: Option A.

Common misconception. n/log n is easy to misplace. It sits *above* √n but *below* n; treating the /log n factor as making it slower than √n is the usual error. Verify with a concrete value: at n = 2^20, n/log₂n ≈ 52428 while √n = 1024.

ALG-U1-Q04MCQmedium

Which of the following statements is FALSE?

  1. n! = O(nⁿ)
  2. log(n!) = Θ(n log n)
  3. 2ⁿ⁺¹ = O(2ⁿ)
  4. 2²ⁿ = O(2ⁿ)
Show answer & solution

Detailed solution

Concept. Exponential bases cannot be changed by a constant factor, and log(n!) is sandwiched by Stirling's bounds.

Step by step.

  1. n! = 1·2···n ≤ n·n···n = nⁿ, so A is true.
  2. Stirling gives n! ≥ (n/e)ⁿ, so log(n!) = Θ(n log n); B is true.
  3. 2ⁿ⁺¹ = 2·2ⁿ, a constant multiple, so C is true.
  4. 2²ⁿ = 4ⁿ and 4ⁿ/2ⁿ = 2ⁿ → ∞, so 2²ⁿ ≠ O(2ⁿ); D is false.

Answer: D is the FALSE statement.

Common misconception. A constant added to the *exponent* is a constant factor in the value (2ⁿ⁺¹ = 2·2ⁿ), but a constant multiplying the exponent is an exponential factor (2²ⁿ = 4ⁿ). Mixing these two up is the standard trap.

ALG-U1-Q15MCQhard

Let f(n) = n^(log₂ n) and g(n) = n^1000. Which of the following is TRUE?

  1. f(n) = O(g(n))
  2. f(n) = Ω(g(n)) and f(n) ≠ O(g(n))
  3. f(n) = Θ(g(n))
  4. f(n) = o(g(n))
Show answer & solution

Detailed solution

Concept. Both are n raised to a power; compare the exponents log₂n and 1000.

Step by step.

  1. Write both as n^(exponent): f has exponent log₂n, g has exponent 1000.
  2. log₂n > 1000 once n > 2^1000.
  3. Beyond that point f(n) > g(n), so f is not O(g).
  4. f(n)/g(n) = n^(log₂n − 1000) → ∞, so f(n) = Ω(g(n)) and f(n) ≠ O(g(n)).

Answer: Option B.

Common misconception. A fixed polynomial n^1000 looks enormous but any polylog exponent eventually overtakes a constant exponent. The other classic trap is assuming n^(log n) is still polynomial — it is quasi-polynomial, growing faster than every n^k.

ALG-U1-Q16MSQmedium

Which of the following statements are TRUE?

  1. If f(n) = O(g(n)) then g(n) = Ω(f(n)).
  2. If f(n) = Θ(g(n)) then 2^(f(n)) = Θ(2^(g(n))).
  3. n^(1/2) = O(n^(2/3)).
  4. log(n!) = O(n log n).
Show answer & solution

Detailed solution

Concept. Definitions of O, Ω, Θ, and Stirling's bound for log(n!).

Step by step.

  1. A: f = O(g) means f(n) ≤ c·g(n) eventually; dividing by c gives g(n) ≥ (1/c)f(n), i.e. g = Ω(f). TRUE.
  2. B: take f(n) = n, g(n) = 2n. Then 2^(f(n)) = 2ⁿ and 2^(g(n)) = 4ⁿ, and 4ⁿ/2ⁿ = 2ⁿ → ∞, so they are not Θ of each other. FALSE.
  3. C: 1/2 < 2/3, so n^(1/2)/n^(2/3) = n^(−1/6) → 0. TRUE.
  4. D: log(n!) ≤ log(nⁿ) = n log n. TRUE.

Answer: A, C and D are TRUE; B is FALSE.

Common misconception. B is the classic failure: Θ is preserved by addition and multiplication but **not** by exponentiation. Equal growth of f and g allows a multiplicative gap, which exponentiation turns into an unbounded ratio.

ALG-U1-Q20MSQeasy

Which of the following functions are O(n log n)?

  1. 5n log n + 100n
  2. n²/log n
  3. log(n!)
  4. 2^(log₂ n)
Show answer & solution

Detailed solution

Concept. Check whether each function is bounded above by a constant multiple of n log n.

Step by step.

  1. 5n log n + 100n ≤ 105 n log n for n ≥ 2. YES.
  2. (n²/log n)/(n log n) = n/(log n)² → ∞, so it is NOT O(n log n). NO.
  3. log(n!) = Θ(n log n) by Stirling, hence O(n log n). YES.
  4. 2^(log₂n) = n ≤ n log n for n ≥ 2. YES.

Answer: A, C and D.

Common misconception. n²/log n is larger than n log n even though the log n sits in the denominator — dividing by a log does not bring a quadratic down to n log n.

ALG-U1-Q26MCQeasy

Which of the following is the formal definition of f(n) = O(g(n)) for asymptotically positive functions?

  1. There exist constants c > 0 and n₀ ≥ 0 such that f(n) ≤ c·g(n) for all n ≥ n₀.
  2. For every constant c > 0 there exists n₀ such that f(n) ≤ c·g(n) for all n ≥ n₀.
  3. There exist constants c > 0 and n₀ ≥ 0 such that f(n) ≥ c·g(n) for all n ≥ n₀.
  4. limn→∞ f(n)/g(n) = 0.
Show answer & solution

Detailed solution

Concept. Big-O is an upper bound that is allowed to be off by a fixed constant factor, and it only has to hold from some point onwards. One pair (c, n₀) that works is enough — the constant does not have to be beaten by every possible choice.

Step by step.

  1. Option A is exactly that statement: ∃c > 0, ∃n₀ such that f(n) ≤ c·g(n) beyond n₀.
  2. Option B quantifies c universally, so it demands f(n) ≤ c·g(n) even for c = 0.001. That is little-o, f(n) = o(g(n)), a strictly stronger claim.
  3. Option C has the inequality reversed, which defines f(n) = Ω(g(n)).
  4. Option D is the ratio test for little-o. It implies big-O but is not equivalent to it: f(n) = 2n is O(n) while f(n)/g(n) = 2 does not tend to 0.

Answer: Option (A) — the existential definition of an asymptotic upper bound.

Common misconception. Reading the ∃c of big-O as ∀c, which silently upgrades the claim to little-o, or reversing the inequality and landing on Ω. The constant is a witness you are free to choose, not a quantity you must satisfy for all values.

ALG-U1-Q27MCQeasy

Let f(n) = n^(3/2) and g(n) = n (log₂ n)². Which of the following is TRUE?

  1. f(n) = Θ(g(n))
  2. f(n) = O(g(n)) but f(n) ≠ Θ(g(n))
  3. g(n) = o(f(n))
  4. f(n) = o(g(n))
Show answer & solution

Detailed solution

Concept. Two functions are compared by the limit of their ratio. A ratio that blows up means the numerator grows faster; a ratio that tends to 0 means the denominator does.

Step by step.

  1. Form the ratio f(n)/g(n) = n^(3/2) / (n (log₂ n)²) = √n / (log₂ n)².
  2. Every polynomial in n beats every power of a logarithm: for n = 2^(m) the ratio is 2^(m/2)/m² → ∞.
  3. So f(n)/g(n) → ∞, which is precisely g(n) = o(f(n)).
  4. Consequently f(n) = ω(g(n)) and the two functions are not within a constant factor of each other.

Answer: Option (C) — g(n) = o(f(n)).

Common misconception. Treating (log₂ n)² as if it were a polynomial factor comparable with √n. A logarithm squared is still far smaller than any positive power of n, so option (A) and option (D) both fail; option (B) reverses the direction.

ALG-U1-Q28MCQmedium

For every integer n ≥ 2 define f(n) = n^(1 + 1/log₂ n). Then

  1. f(n) = Θ(n)
  2. f(n) = Θ(n log n)
  3. f(n) = Θ(n²)
  4. f(n) = Θ(2^(n))
Show answer & solution

Detailed solution

Concept. A power of n whose exponent depends on n is best read in base 2: write n = 2^(log₂ n) and push the exponent through.

Step by step.

  1. Split the exponent: n^(1 + 1/log₂ n) = n · n^(1/log₂ n).
  2. Now n^(1/log₂ n) = 2^((log₂ n)·(1/log₂ n)) = 2^(1) = 2, a constant.
  3. Hence f(n) = 2n for every n ≥ 2.
  4. A constant multiple of n is Θ(n).

Answer: Option (A) — f(n) = 2n = Θ(n).

Common misconception. Assuming that an exponent containing 1/log₂ n must produce sub-linear or super-linear growth and guessing Θ(n log n) or Θ(n²). The exponent is not a fixed power: it shrinks exactly fast enough to cancel the log₂ n in the base change, leaving the constant 2.

ALG-U1-Q29MCQmedium

Which of the following statements is FALSE?

  1. n^(0.1) = O(log₂ n)
  2. log₂(n³) = Θ(log₂ n)
  3. 3^(n) = ω(n^(100))
  4. √n = O(n/log₂ n)
Show answer & solution

Detailed solution

Concept. Each claim is settled by the limit of the ratio of the two sides. Anything with a positive power of n outgrows any power of log n, and any exponential outgrows any polynomial.

Step by step.

  1. (A) n^(0.1)/log₂ n → ∞ because a polynomial dominates a logarithm. So n^(0.1) is ω(log n), never O(log n). FALSE.
  2. (B) log₂(n³) = 3 log₂ n, a constant multiple of log₂ n. TRUE.
  3. (C) 3^(n)/n^(100) → ∞, so n^(100) = o(3^(n)). TRUE.
  4. (D) √n / (n/log₂ n) = log₂ n / √n → 0, so √n = O(n/log₂ n). TRUE.

Answer: Option (A) is the false statement.

Common misconception. Judging by a few small values: at n = 10^(6) the ratio n^(0.1)/log₂ n is still below 1, which tempts a "yes" for (A). Asymptotics is about the limit, not about the first million values — the ratio eventually climbs without bound.

ALG-U1-Q30MCQhard

Which of the following functions grows fastest as n → ∞?

  1. 2^(n)
  2. n^(log₂ n)
  3. (log₂ n)^(n)
  4. n!
Show answer & solution

Detailed solution

Concept. When the bases differ and the exponents contain n, compare the base-2 logarithms of the four functions. A larger logarithm means a faster-growing function.

Step by step.

  1. (A) log₂ 2^(n) = n.
  2. (B) log₂ n^(log₂ n) = (log₂ n)².
  3. (C) log₂ (log₂ n)^(n) = n · log₂ log₂ n.
  4. (D) Stirling: log₂(n!) = n log₂ n − O(n), i.e. Θ(n log₂ n).
  5. Order the logarithms: (log₂ n)² is the smallest, then n, then n log₂ log₂ n, and n log₂ n is the largest.
  6. So n! is the fastest-growing of the four.

Answer: Option (D) — n!.

Common misconception. Picking 2^(n) because "exponential beats everything", or n^(log₂ n) because it has a power of n in the exponent. Both are beaten by n!, whose logarithm n log₂ n exceeds n log₂ log₂ n and (log₂ n)².

ALG-U1-Q41MSQeasy

Which of the following functions are Ω(n²)?

  1. n²/1000
  2. n (log₂ n)³
  3. 2^(n)
  4. n^(5/2)
Show answer & solution

Detailed solution

Concept. A function is Ω(n²) when it is bounded below by a constant multiple of n² from some point on. A small constant multiplier does not matter; what matters is the growth rate.

Step by step.

  1. (A) n²/1000 = (1/1000)·n² is a constant multiple of n²: Ω(n²). TRUE.
  2. (B) n (log₂ n)³ / n² = (log₂ n)³/n → 0, so it grows strictly slower: NOT Ω(n²).
  3. (C) 2^(n)/n² → ∞: TRUE.
  4. (D) n^(2.5)/n² = √n → ∞: TRUE.

Answer: Options (A), (C) and (D).

Common misconception. Rejecting (A) because of the tiny constant 1/1000. Asymptotic bounds ignore constant factors; only the growth rate counts.

ALG-U1-Q42MSQmedium

Which of the following statements are TRUE for asymptotically positive functions?

  1. f(n) = Θ(g(n)) if and only if f(n) = O(g(n)) and g(n) = O(f(n)).
  2. If f(n) = o(g(n)) then f(n) = O(g(n)) and f(n) ≠ Ω(g(n)).
  3. For every pair of functions f and g, either f(n) = O(g(n)) or g(n) = O(f(n)).
  4. If f(n) = O(g(n)) and g(n) = O(h(n)) then f(n) = O(h(n)).
Show answer & solution

Detailed solution

Concept. The asymptotic relations are preorders on functions. Θ is the symmetric part of O, O is transitive, and O is not a total order because two functions can be incomparable.

Step by step.

  1. (A) Θ means bounded above and below by constant multiples, which is exactly f = O(g) together with g = O(f). TRUE.
  2. (B) f = o(g) means f/g → 0, which gives f = O(g) at once and rules out f = Ω(g) (that would need f/g bounded below). TRUE.
  3. (C) Fails: take f(n) = n and g(n) = n^(1 + sin n). The ratio g/f = n^(sin n) oscillates between 1/n and n, so neither f = O(g) nor g = O(f) holds. FALSE.
  4. (D) Chaining the two constants gives f(n) ≤ c₁g(n) ≤ c₁c₂h(n) eventually. TRUE.

Answer: Options (A), (B) and (D).

Common misconception. Assuming O behaves like ≤ on numbers, which would make it a total order. It is only a preorder: transitivity and reflexivity hold, but two functions with wildly oscillating ratio are incomparable.

ALG-U1-Q45MSQhard

Which of the following statements are TRUE?

  1. n^(log₂ 3) = O(n^(1.6))
  2. 3^(n) = O(2^(n))
  3. 2^(3n) = Θ(8^(n))
  4. If f(n) = ω(g(n)) then f(n)/g(n) → ∞.
Show answer & solution

Detailed solution

Concept. Compare by ratio, and remember that two exponentials with different bases are never within a constant factor of each other, while two exponentials that differ only by rewriting the same expression are identical functions.

Step by step.

  1. (A) log₂ 3 ≈ 1.585 < 1.6, so n^(log₂ 3)/n^(1.6) = n^(−0.015) → 0. TRUE.
  2. (B) 3^(n)/2^(n) = (3/2)^(n) → ∞, so 2^(n) = o(3^(n)) and the claimed direction is reversed. FALSE.
  3. (C) 2^(3n) = (2³)^(n) = 8^(n), the very same function. TRUE.
  4. (D) That is the definition of little-omega: for every c > 0, f(n) > c g(n) eventually, which forces the ratio to diverge. TRUE.

Answer: Options (A), (C) and (D).

Common misconception. Reading O(2^(n)) as "exponential, so anything exponential is fine". A constant factor in the exponent is not a constant factor in the function: 3^(n) and 2^(n) differ by (3/2)^(n), which is unbounded.

ALG-U1-Q05MCQeasy

The recurrence T(n) = 2T(n/2) + n, with T(1) = 1, has the solution

  1. Θ(n log n)
  2. Θ(n²)
  3. Θ(n)
  4. Θ(log n)

Concept. Master Theorem with a = 2, b = 2: compare f(n) against n^(log_b a).

Step by step.

  1. a = 2, b = 2, so n^(log₂2) = n¹.
  2. f(n) = n = Θ(n¹): this is Case 2 (equal growth).

Common misconception. Assuming the unweighted greedy carries over. The exchange argument for earliest finish uses the count of intervals, which is meaningless once weights differ.

Show answer & solution

Detailed solution

Concept. Finishing as early as possible leaves the largest remaining window, so the earliest-finish choice is safe: some optimal solution contains it.

ALG-U3-Q20MCQeasy

The optimal merge pattern for n sorted files is obtained by repeatedly merging:

  1. the two largest files
  2. the two smallest files
  3. the largest file with the smallest file
  4. any two files, chosen in input order
Show answer & solution

Detailed solution

Concept. Each record in a file is moved once per merge in which its file takes part, so files merged early are charged repeatedly. Small files must therefore be merged first, exactly as small frequencies must be deepest in a Huffman tree.

Step by step.

  1. The total cost is the weighted external path length of the merge tree, with file sizes as weights.
  2. Minimising that sum places the smallest weights deepest, which is achieved by merging the two smallest available files at every step.
  3. Merging the two largest first (A) puts the biggest weights at the greatest depths and maximises the cost.
  4. The mixed rule (C) and the input-order rule (D) are not optimal in general.

Answer: Option (B).

Common misconception. Merging in input order, which is what a naive two-way merge sort of the files does. That is correct but not cost-optimal.

Concept map used to build the questions

  • What makes a problem a DP problem. Optimal substructure — an optimal solution contains optimal solutions to subproblems, proved by a cut-and-paste exchange — and overlapping subproblems, which is what makes memoisation worth more than plain divide-and-conquer. The state must be a summary small enough to index a table: an interval for the chain, a pair of prefix lengths for the LCS, a prefix and a residual capacity for the knapsack, a pair of vertices and a set of allowed intermediates for the shortest paths.
  • Interval DP and its cost term. m[i][j] = min_k ( m[i][k] + m[k+1][j] + pᵢ₋₁·p_k·p_j ): fill by increasing interval length, and remember that the third term is the cost of the last multiplication, which is the step candidates most often forget. The count of parenthesizations is Catalan, so the table is what makes the problem tractable at all.
  • Prefix DP. c[i][j] for the LCS: a match adds one to the diagonal, a mismatch takes the better of the two neighbouring cells. The same table answers longest palindromic subsequence (apply it to the string and its reverse) and edit distance (change the match/mismatch costs), and its space can be cut to two rows, with Hirschberg's divide-and-conquer recovering the sequence itself.
  • Capacity DP and pseudo-polynomial time. K[i][w] for the knapsack: row i−1 means "each item at most once", row i means "reuse allowed", which is the whole difference between 0-1 and unbounded knapsack. The Θ(nW) bound is polynomial in the numeric capacity but exponential in the number of bits used to write it, so it does not contradict NP-hardness.
  • All-pairs shortest paths. Floyd–Warshall adds one vertex at a time to the set of allowed intermediate vertices; the recurrence is the same loop over (OR, AND) for transitive closure. Negative edges are fine, a negative cycle is not — it is detected by d[i][i] < 0 — and Johnson's algorithm is the alternative route that repairs the weights with potentials so that Dijkstra can be reused.
  • Connections. The DP table is the same object in all four subtopics: a state space with an order in which it can be filled. The same reasoning decides when a greedy algorithm can replace it — fractional knapsack and Huffman coding are greedy, their 0-1 and prefix-code counterparts are not — and Floyd–Warshall reappears in Databases as the fixpoint of a recursive view and in Compiler Design as the data-flow fixpoint.
