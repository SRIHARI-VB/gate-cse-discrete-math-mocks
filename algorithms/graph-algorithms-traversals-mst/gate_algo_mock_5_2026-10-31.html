ALG-U1-Q01MCQeasy

Consider f(n) = 3n² + 5n log n + 7. Which of the following is TRUE?

  1. f(n) = Θ(n²)
  2. f(n) = Θ(n log n)
  3. f(n) = Θ(n³)
  4. f(n) = Θ(n)
Show answer & solution

Detailed solution

Concept. Growth of a sum is governed by its fastest-growing term (the dominant term).

Step by step.

  1. The three terms grow as n², n log n and a constant.
  2. n log n = o(n²), because (n log n)/n² = (log n)/n → 0.
  3. So f(n) is squeezed between 3n² and (3+ε)n² for large n.
  4. Hence f(n) = Θ(n²).

Answer: Θ(n²) — option A.

Common misconception. Adding a lower-order term such as 5n log n never changes the Θ-class. Students who sum the exponents or pick the largest coefficient by eye get B or C.

ALG-U1-Q02MCQeasy

If f(n) = Θ(g(n)) and g(n) = Θ(h(n)), which statement is necessarily TRUE?

  1. f(n) = Θ(h(n))
  2. f(n) = O(h(n)) but f(n) ≠ Θ(h(n))
  3. f(n) = o(h(n))
  4. Nothing can be concluded about f and h
Show answer & solution

Detailed solution

Concept. Θ is an equivalence relation: it is reflexive, symmetric and transitive.

Step by step.

  1. f = Θ(g) gives constants c₁, c₂, n₀ with c₁g(n) ≤ f(n) ≤ c₂g(n) for n ≥ n₀.
  2. g = Θ(h) gives d₁h(n) ≤ g(n) ≤ d₂h(n) for n ≥ n₁.
  3. Chain them for n ≥ max(n₀, n₁): c₁d₁h(n) ≤ f(n) ≤ c₂d₂h(n).
  4. That is exactly f(n) = Θ(h(n)).

Answer: f(n) = Θ(h(n)) — option A.

Common misconception. f = o(h) is strictly stronger than f = Θ(h) and does not follow. Θ gives a two-sided constant-factor sandwich, so it can never collapse to a little-o relation.

ALG-U1-Q03MCQmedium

Which is the correct increasing order of growth (slowest first) for large n?

  1. log log n < log n < √n < n/log n < n
  2. log n < log log n < √n < n < n/log n
  3. log log n < √n < log n < n/log n < n
  4. log log n < log n < n/log n < √n < n
Show answer & solution

Detailed solution

Concept. Compare functions by taking ratios (or logs of both sides) as n → ∞.

Step by step.

  1. log log n = o(log n): log log n / log n → 0.
  2. log n = o(√n): with n = 2^m, m / 2^(m/2) → 0.
  3. √n = o(n/log n): (n/log n)/√n = √n / log n → ∞.
  4. n/log n = o(n) since 1/log n → 0.
  5. Chaining gives log log n < log n < √n < n/log n < n.

Answer: Option A.

Common misconception. n/log n is easy to misplace. It sits *above* √n but *below* n; treating the /log n factor as making it slower than √n is the usual error. Verify with a concrete value: at n = 2^20, n/log₂n ≈ 52428 while √n = 1024.

ALG-U1-Q04MCQmedium

Which of the following statements is FALSE?

  1. n! = O(nⁿ)
  2. log(n!) = Θ(n log n)
  3. 2ⁿ⁺¹ = O(2ⁿ)
  4. 2²ⁿ = O(2ⁿ)
Show answer & solution

Detailed solution

Concept. Exponential bases cannot be changed by a constant factor, and log(n!) is sandwiched by Stirling's bounds.

Step by step.

  1. n! = 1·2···n ≤ n·n···n = nⁿ, so A is true.
  2. Stirling gives n! ≥ (n/e)ⁿ, so log(n!) = Θ(n log n); B is true.
  3. 2ⁿ⁺¹ = 2·2ⁿ, a constant multiple, so C is true.
  4. 2²ⁿ = 4ⁿ and 4ⁿ/2ⁿ = 2ⁿ → ∞, so 2²ⁿ ≠ O(2ⁿ); D is false.

Answer: D is the FALSE statement.

Common misconception. A constant added to the *exponent* is a constant factor in the value (2ⁿ⁺¹ = 2·2ⁿ), but a constant multiplying the exponent is an exponential factor (2²ⁿ = 4ⁿ). Mixing these two up is the standard trap.

ALG-U1-Q15MCQhard

Let f(n) = n^(log₂ n) and g(n) = n^1000. Which of the following is TRUE?

  1. f(n) = O(g(n))
  2. f(n) = Ω(g(n)) and f(n) ≠ O(g(n))
  3. f(n) = Θ(g(n))
  4. f(n) = o(g(n))
Show answer & solution

Detailed solution

Concept. Both are n raised to a power; compare the exponents log₂n and 1000.

Step by step.

  1. Write both as n^(exponent): f has exponent log₂n, g has exponent 1000.
  2. log₂n > 1000 once n > 2^1000.
  3. Beyond that point f(n) > g(n), so f is not O(g).
  4. f(n)/g(n) = n^(log₂n − 1000) → ∞, so f(n) = Ω(g(n)) and f(n) ≠ O(g(n)).

Answer: Option B.

Common misconception. A fixed polynomial n^1000 looks enormous but any polylog exponent eventually overtakes a constant exponent. The other classic trap is assuming n^(log n) is still polynomial — it is quasi-polynomial, growing faster than every n^k.

ALG-U1-Q16MSQmedium

Which of the following statements are TRUE?

  1. If f(n) = O(g(n)) then g(n) = Ω(f(n)).
  2. If f(n) = Θ(g(n)) then 2^(f(n)) = Θ(2^(g(n))).
  3. n^(1/2) = O(n^(2/3)).
  4. log(n!) = O(n log n).
Show answer & solution

Detailed solution

Concept. Definitions of O, Ω, Θ, and Stirling's bound for log(n!).

Step by step.

  1. A: f = O(g) means f(n) ≤ c·g(n) eventually; dividing by c gives g(n) ≥ (1/c)f(n), i.e. g = Ω(f). TRUE.
  2. B: take f(n) = n, g(n) = 2n. Then 2^(f(n)) = 2ⁿ and 2^(g(n)) = 4ⁿ, and 4ⁿ/2ⁿ = 2ⁿ → ∞, so they are not Θ of each other. FALSE.
  3. C: 1/2 < 2/3, so n^(1/2)/n^(2/3) = n^(−1/6) → 0. TRUE.
  4. D: log(n!) ≤ log(nⁿ) = n log n. TRUE.

Answer: A, C and D are TRUE; B is FALSE.

Common misconception. B is the classic failure: Θ is preserved by addition and multiplication but **not** by exponentiation. Equal growth of f and g allows a multiplicative gap, which exponentiation turns into an unbounded ratio.

ALG-U1-Q20MSQeasy

Which of the following functions are O(n log n)?

  1. 5n log n + 100n
  2. n²/log n
  3. log(n!)
  4. 2^(log₂ n)
Show answer & solution

Detailed solution

Concept. Check whether each function is bounded above by a constant multiple of n log n.

Step by step.

  1. 5n log n + 100n ≤ 105 n log n for n ≥ 2. YES.
  2. (n²/log n)/(n log n) = n/(log n)² → ∞, so it is NOT O(n log n). NO.
  3. log(n!) = Θ(n log n) by Stirling, hence O(n log n). YES.
  4. 2^(log₂n) = n ≤ n log n for n ≥ 2. YES.

Answer: A, C and D.

Common misconception. n²/log n is larger than n log n even though the log n sits in the denominator — dividing by a log does not bring a quadratic down to n log n.

ALG-U1-Q26MCQeasy

Which of the following is the formal definition of f(n) = O(g(n)) for asymptotically positive functions?

  1. There exist constants c > 0 and n₀ ≥ 0 such that f(n) ≤ c·g(n) for all n ≥ n₀.
  2. For every constant c > 0 there exists n₀ such that f(n) ≤ c·g(n) for all n ≥ n₀.
  3. There exist constants c > 0 and n₀ ≥ 0 such that f(n) ≥ c·g(n) for all n ≥ n₀.
  4. limn→∞ f(n)/g(n) = 0.
Show answer & solution

Detailed solution

Concept. Big-O is an upper bound that is allowed to be off by a fixed constant factor, and it only has to hold from some point onwards. One pair (c, n₀) that works is enough — the constant does not have to be beaten by every possible choice.

Step by step.

  1. Option A is exactly that statement: ∃c > 0, ∃n₀ such that f(n) ≤ c·g(n) beyond n₀.
  2. Option B quantifies c universally, so it demands f(n) ≤ c·g(n) even for c = 0.001. That is little-o, f(n) = o(g(n)), a strictly stronger claim.
  3. Option C has the inequality reversed, which defines f(n) = Ω(g(n)).
  4. Option D is the ratio test for little-o. It implies big-O but is not equivalent to it: f(n) = 2n is O(n) while f(n)/g(n) = 2 does not tend to 0.

Answer: Option (A) — the existential definition of an asymptotic upper bound.

Common misconception. Reading the ∃c of big-O as ∀c, which silently upgrades the claim to little-o, or reversing the inequality and landing on Ω. The constant is a witness you are free to choose, not a quantity you must satisfy for all values.

ALG-U1-Q27MCQeasy

Let f(n) = n^(3/2) and g(n) = n (log₂ n)². Which of the following is TRUE?

  1. f(n) = Θ(g(n))
  2. f(n) = O(g(n)) but f(n) ≠ Θ(g(n))
  3. g(n) = o(f(n))
  4. f(n) = o(g(n))
Show answer & solution

Detailed solution

Concept. Two functions are compared by the limit of their ratio. A ratio that blows up means the numerator grows faster; a ratio that tends to 0 means the denominator does.

Step by step.

  1. Form the ratio f(n)/g(n) = n^(3/2) / (n (log₂ n)²) = √n / (log₂ n)².
  2. Every polynomial in n beats every power of a logarithm: for n = 2^(m) the ratio is 2^(m/2)/m² → ∞.
  3. So f(n)/g(n) → ∞, which is precisely g(n) = o(f(n)).
  4. Consequently f(n) = ω(g(n)) and the two functions are not within a constant factor of each other.

Answer: Option (C) — g(n) = o(f(n)).

Common misconception. Treating (log₂ n)² as if it were a polynomial factor comparable with √n. A logarithm squared is still far smaller than any positive power of n, so option (A) and option (D) both fail; option (B) reverses the direction.

ALG-U1-Q28MCQmedium

For every integer n ≥ 2 define f(n) = n^(1 + 1/log₂ n). Then

  1. f(n) = Θ(n)
  2. f(n) = Θ(n log n)
  3. f(n) = Θ(n²)
  4. f(n) = Θ(2^(n))
Show answer & solution

Detailed solution

Concept. A power of n whose exponent depends on n is best read in base 2: write n = 2^(log₂ n) and push the exponent through.

Step by step.

  1. Split the exponent: n^(1 + 1/log₂ n) = n · n^(1/log₂ n).
  2. Now n^(1/log₂ n) = 2^((log₂ n)·(1/log₂ n)) = 2^(1) = 2, a constant.
  3. Hence f(n) = 2n for every n ≥ 2.
  4. A constant multiple of n is Θ(n).

Answer: Option (A) — f(n) = 2n = Θ(n).

Common misconception. Assuming that an exponent containing 1/log₂ n must produce sub-linear or super-linear growth and guessing Θ(n log n) or Θ(n²). The exponent is not a fixed power: it shrinks exactly fast enough to cancel the log₂ n in the base change, leaving the constant 2.

ALG-U1-Q29MCQmedium

Which of the following statements is FALSE?

  1. n^(0.1) = O(log₂ n)
  2. log₂(n³) = Θ(log₂ n)
  3. 3^(n) = ω(n^(100))
  4. √n = O(n/log₂ n)
Show answer & solution

Detailed solution

Concept. Each claim is settled by the limit of the ratio of the two sides. Anything with a positive power of n outgrows any power of log n, and any exponential outgrows any polynomial.

Step by step.

  1. (A) n^(0.1)/log₂ n → ∞ because a polynomial dominates a logarithm. So n^(0.1) is ω(log n), never O(log n). FALSE.
  2. (B) log₂(n³) = 3 log₂ n, a constant multiple of log₂ n. TRUE.
  3. (C) 3^(n)/n^(100) → ∞, so n^(100) = o(3^(n)). TRUE.
  4. (D) √n / (n/log₂ n) = log₂ n / √n → 0, so √n = O(n/log₂ n). TRUE.

Answer: Option (A) is the false statement.

Common misconception. Judging by a few small values: at n = 10^(6) the ratio n^(0.1)/log₂ n is still below 1, which tempts a "yes" for (A). Asymptotics is about the limit, not about the first million values — the ratio eventually climbs without bound.

ALG-U1-Q30MCQhard

Which of the following functions grows fastest as n → ∞?

  1. 2^(n)
  2. n^(log₂ n)
  3. (log₂ n)^(n)
  4. n!
Show answer & solution

Detailed solution

Concept. When the bases differ and the exponents contain n, compare the base-2 logarithms of the four functions. A larger logarithm means a faster-growing function.

Step by step.

  1. (A) log₂ 2^(n) = n.
  2. (B) log₂ n^(log₂ n) = (log₂ n)².
  3. (C) log₂ (log₂ n)^(n) = n · log₂ log₂ n.
  4. (D) Stirling: log₂(n!) = n log₂ n − O(n), i.e. Θ(n log₂ n).
  5. Order the logarithms: (log₂ n)² is the smallest, then n, then n log₂ log₂ n, and n log₂ n is the largest.
  6. So n! is the fastest-growing of the four.

Answer: Option (D) — n!.

Common misconception. Picking 2^(n) because "exponential beats everything", or n^(log₂ n) because it has a power of n in the exponent. Both are beaten by n!, whose logarithm n log₂ n exceeds n log₂ log₂ n and (log₂ n)².

ALG-U1-Q41MSQeasy

Which of the following functions are Ω(n²)?

  1. n²/1000
  2. n (log₂ n)³
  3. 2^(n)
  4. n^(5/2)
Show answer & solution

Detailed solution

Concept. A function is Ω(n²) when it is bounded below by a constant multiple of n² from some point on. A small constant multiplier does not matter; what matters is the growth rate.

Step by step.

  1. (A) n²/1000 = (1/1000)·n² is a constant multiple of n²: Ω(n²). TRUE.
  2. (B) n (log₂ n)³ / n² = (log₂ n)³/n → 0, so it grows strictly slower: NOT Ω(n²).
  3. (C) 2^(n)/n² → ∞: TRUE.
  4. (D) n^(2.5)/n² = √n → ∞: TRUE.

Answer: Options (A), (C) and (D).

Common misconception. Rejecting (A) because of the tiny constant 1/1000. Asymptotic bounds ignore constant factors; only the growth rate counts.

ALG-U1-Q42MSQmedium

Which of the following statements are TRUE for asymptotically positive functions?

  1. f(n) = Θ(g(n)) if and only if f(n) = O(g(n)) and g(n) = O(f(n)).
  2. If f(n) = o(g(n)) then f(n) = O(g(n)) and f(n) ≠ Ω(g(n)).
  3. For every pair of functions f and g, either f(n) = O(g(n)) or g(n) = O(f(n)).
  4. If f(n) = O(g(n)) and g(n) = O(h(n)) then f(n) = O(h(n)).
Show answer & solution

Detailed solution

Concept. The asymptotic relations are preorders on functions. Θ is the symmetric part of O, O is transitive, and O is not a total order because two functions can be incomparable.

Step by step.

  1. (A) Θ means bounded above and below by constant multiples, which is exactly f = O(g) together with g = O(f). TRUE.
  2. (B) f = o(g) means f/g → 0, which gives f = O(g) at once and rules out f = Ω(g) (that would need f/g bounded below). TRUE.
  3. (C) Fails: take f(n) = n and g(n) = n^(1 + sin n). The ratio g/f = n^(sin n) oscillates between 1/n and n, so neither f = O(g) nor g = O(f) holds. FALSE.
  4. (D) Chaining the two constants gives f(n) ≤ c₁g(n) ≤ c₁c₂h(n) eventually. TRUE.

Answer: Options (A), (B) and (D).

Common misconception. Assuming O behaves like ≤ on numbers, which would make it a total order. It is only a preorder: transitivity and reflexivity hold, but two functions with wildly oscillating ratio are incomparable.

ALG-U1-Q45MSQhard

Which of the following statements are TRUE?

  1. n^(log₂ 3) = O(n^(1.6))
  2. 3^(n) = O(2^(n))
  3. 2^(3n) = Θ(8^(n))
  4. If f(n) = ω(g(n)) then f(n)/g(n) → ∞.
Show answer & solution

Detailed solution

Concept. Compare by ratio, and remember that two exponentials with different bases are never within a constant factor of each other, while two exponentials that differ only by rewriting the same expression are identical functions.

Step by step.

  1. (A) log₂ 3 ≈ 1.585 < 1.6, so n^(log₂ 3)/n^(1.6) = n^(−0.015) → 0. TRUE.
  2. (B) 3^(n)/2^(n) = (3/2)^(n) → ∞, so 2^(n) = o(3^(n)) and the claimed direction is reversed. FALSE.
  3. (C) 2^(3n) = (2³)^(n) = 8^(n), the very same function. TRUE.
  4. (D) That is the definition of little-omega: for every c > 0, f(n) > c g(n) eventually, which forces the ratio to diverge. TRUE.

Answer: Options (A), (C) and (D).

Common misconception. Reading O(2^(n)) as "exponential, so anything exponential is fine". A constant factor in the exponent is not a constant factor in the function: 3^(n) and 2^(n) differ by (3/2)^(n), which is unbounded.

ALG-U1-Q05MCQeasy

The recurrence T(n) = 2T(n/2) + n, with T(1) = 1, has the solution

  1. Θ(n log n)
  2. Θ(n²)
  3. Θ(n)
  4. Θ(log n)
Show answer & solution

Detailed solution

Concept. Master Theorem with a = 2, b = 2: compare f(n) against n^(log_b a).

Step by step.

  1. a = 2, b = 2, so n^(log₂2) = n¹.
  2. f(n) = n = Θ(n¹): this is Case 2 (equal growth).
  3. Case 2 gives T(n) = Θ(n^(log_b a) · log n) = Θ(n log n).
  4. Check by recursion tree: log₂n levels each costing n.

  3. Johnson's algorithm reweights the edges with a potential function obtained from one Bellman–Ford run from a new source, then runs Dijkstra from every vertex, in O(V² log V + VE) with a binary heap.
  4. If a negative-weight cycle is reachable, the final Floyd–Warshall matrix satisfies d[i][i] < 0 for every vertex i on that cycle.
Show answer & solution

Detailed solution

Concept. Three different all-pairs strategies, each with its own precondition: BFS exploits unit weights, Dijkstra requires non-negative weights, Johnson repairs negative weights before using Dijkstra, and Floyd–Warshall needs no precondition but detects negative cycles instead of returning nonsense.

Step by step.

  1. (A) TRUE. BFS from each vertex costs O(V·(V+E)), which on a sparse graph is far below Θ(V³); Floyd–Warshall ignores the sparsity.
  2. (B) FALSE. Dijkstra finalises a vertex when it is popped, assuming no later path can be shorter. Take A→B (1), A→C (2), C→B (−2): Dijkstra from A pops B at distance 1 and finalises it, although the true distance is 0 through C. One negative edge is enough; no cycle is needed.
  3. (C) TRUE. Bellman–Ford from a new source s with 0-weight edges to all vertices gives potentials h(v) = δ(s,v) satisfying w(u,v) + h(u) − h(v) ≥ 0. Reweighting preserves shortest paths, so V Dijkstra runs give O(V² log V + VE) with a binary heap.
  4. (D) TRUE. A vertex i on a negative cycle can reach itself through that cycle with negative total weight, so d[i][i] < 0 after all vertices are allowed as intermediates; vertices not on the cycle keep d[i][i] = 0.

Answer: (A), (C) and (D) are TRUE; (B) is FALSE.

Common misconception. (B) is the persistent error: 'Dijkstra is fine as long as there is no negative cycle' is false — a single negative edge is enough to break it. (D) is often mis-stated as 'd[i][i] < 0 for all i', which would wrongly include vertices off the cycle.

  1. A, B, C, F, E, G, D
  2. A, B, C, F, G, E, D
  3. A, B, D, G, E, C, F
  4. A, B, C, E, G, D, F
Show answer & solution

Detailed solution

Concept. A depth-first search goes as deep as it can before it backtracks, so the discovery order is a preorder walk of the recursion tree: from a vertex it moves to its first unvisited neighbour and only returns when every neighbour of the current vertex is done.

Step by step.

  1. At A the neighbours are B and D; the alphabetically first is B, so A, B.
  2. At B the neighbours are A (visited), C, E; go to C: A, B, C.
  3. At C only F is new: A, B, C, F. F has no other neighbour, so the search backtracks to C and then to B.
  4. At B the next unvisited neighbour is E: A, B, C, F, E.
  5. At E go to G, and at G go to D: A, B, C, F, E, G, D. Everything is visited.

Answer: A, B, C, F, E, G, D — option (A).

Common misconception. Option (C) is the breadth-first order from A. Option (B) is the classic slip: it climbs from F straight to G, but F is adjacent only to C, so the search must backtrack to B and reach G through E.

ALG-U5-Q03MCQmedium

A directed graph has edges A→B, B→C, C→A, A→D, D→C. A depth-first search starts at A and examines out-neighbours in alphabetical order. How is the edge D→C classified?

  1. A tree edge
  2. A back edge
  3. A forward edge
  4. A cross edge
Show answer & solution

Detailed solution

Concept. For an edge u→v met during a DFS: if v is white it is a tree edge; if v is grey it is a back edge; if v is black then it is a forward edge when d[v] > d[u] and a cross edge when d[v] < d[u].

Step by step.

  1. From A the first out-neighbour is B: d[A] = 1, d[B] = 2.
  2. From B go to C: d[C] = 3. From C the edge C→A meets a grey vertex, so it is a back edge; C finishes at time 4 and B at 5.
  3. Back at A, the next out-neighbour is D: d[D] = 6.
  4. The edge D→C now meets C black with d[C] = 3 < d[D] = 6, so C was finished before D was even discovered.
  5. A black target discovered earlier than the source is neither an ancestor (that would be a back edge, and ancestors are grey) nor a descendant (that would need d[C] > d[D]), so the edge is a cross edge.

Answer: A cross edge — option (D).

Common misconception. The tempting error is to reason that because C has an edge back to A, everything reachable from A after C must be "below" C. The DFS had already finished C before D was discovered, so C is not an ancestor of D at all.

  2. Ready set {A}: remove A. That drops B to 1 and D to 0. Removed so far: 1.

  4. Ready set {E}: remove E. Removed: 3.
  5. The queue is now empty, but B and C are still present with in-degree 1 each — they support each other on the cycle B→C→B.

Answer: 3.

Common misconception. Counting four, by removing B once A is gone, ignores that B still has an incoming edge from C. In-degree counts incoming edges, not incoming edges from removed vertices.

ALG-U5-Q14MCQeasy

A weighted undirected graph on vertices A–F has edges AB 4, AD 1, BC 2, BE 3, CF 5, DE 6, EF 7, BD 8, CE 9. What is the total weight of a minimum spanning tree?

  1. 13
  2. 15
  3. 16
  4. 14
Show answer & solution

Detailed solution

Concept. A minimum spanning tree of a connected graph on n vertices has exactly n − 1 edges and is found greedily by the cut property — here, by taking the cheapest edge that does not close a cycle.

Step by step.

  1. Sort the edges: AD 1, BC 2, BE 3, AB 4, CF 5, DE 6, EF 7, BD 8, CE 9.
  2. Take AD 1; take BC 2; take BE 3 (now A, D, B, C, E are connected).
  3. Take AB 4 — it joins the A/D side to the B/C/E side and closes no cycle.
  4. CF 5 is the only edge reaching F, so take it.
  5. Six vertices need five edges; the tree is {AD, BC, BE, AB, CF} with total 1 + 2 + 3 + 4 + 5 = 15.

Answer: 15 — option (B).

Common misconception. Taking the five cheapest edges without checking cycles gives 1 + 2 + 3 + 4 + 5 = 15 here only by luck; the cheap-edge list must still be tested for connectivity. Choosing DE 6 instead of AB 4 gives 17, and dropping CF strands F.

A weighted undirected graph on vertices A–F has edges AB 4, AD 1, BC 2, BE 3, CF 5, DE 6, EF 7, BD 8, CE 9. Prim's algorithm starts at A and at each step adds the cheapest edge leaving the current tree, ties broken alphabetically. In what order are the vertices added?

  1. A, D, B, C, E, F
  2. A, D, B, E, C, F
  3. A, B, C, F, E, D
  4. A, D, B, C, F, E
Show answer & solution

Detailed solution

Concept. Prim's algorithm grows one tree from a fixed root. The candidate set is every edge with exactly one endpoint inside the tree, and the cheapest of those is always safe to add by the cut property.

Step by step.

  1. Tree {A}. Candidate edges AD 1, AB 4; add AD 1, so D joins.
  2. Tree {A, D}. Candidates AB 4, DE 6, BD 8; add AB 4, so B joins.
  3. Tree {A, D, B}. Candidates BC 2, BE 3, DE 6, BD 8; add BC 2, so C joins.
  4. Tree {A, D, B, C}. Candidates BE 3, CF 5, DE 6, CE 9; add BE 3, so E joins.
  5. Tree {A, D, B, C, E}. Candidates CF 5, DE 6, EF 7, CE 9; add CF 5, so F joins.

Answer: A, D, B, C, E, F — option (A).

Common misconception. Option (B) adds E before C, which would require BE 3 to be cheaper than BC 2. Option (D) reverses the last two: once E is in the tree, CF 5 is still cheaper than EF 7.

ALG-U5-Q16MCQeasy

Which property is the reason Prim's algorithm is correct?

  1. Adding, for every vertex, its cheapest incident edge always produces a minimum spanning tree.
  2. The heaviest edge of every cycle must appear in every minimum spanning tree.
  3. Running Prim's algorithm from two different start vertices always produces the same tree, even when edge weights repeat.
  4. For every cut of the graph, a minimum-weight edge crossing that cut belongs to some minimum spanning tree.
Show answer & solution

Detailed solution

Concept. The cut property says that for any partition of the vertices into two non-empty parts, a lightest edge across the partition is safe to include. Prim's algorithm is exactly this property applied to the cut (tree, rest) at every step.

Step by step.

  1. At each step Prim's tree is one side of a cut and the unvisited vertices are the other side; the algorithm adds the lightest edge crossing it.
  2. By the cut property that edge lies in some minimum spanning tree, and extending the argument step by step keeps the partial tree a subtree of an MST.
  3. (A) is false: taking each vertex's cheapest incident edge can produce a cycle. On a triangle with weights 1, 2, 2 every vertex's cheapest edge lies in the triangle, and the three choices form a cycle.
  4. (B) is the opposite of the truth — the cycle property says the heaviest edge of a cycle is the one an MST can avoid.
  5. (C) is false in general: with repeated weights, different start vertices can lead to different minimum spanning trees.

Answer: The cut property — option (D).

Common misconception. (A) confuses the cut property with a vertex-by-vertex greedy rule; the greedy rule needs a cut, not a single vertex. (C) is true only when all weights are distinct, which is exactly the extra hypothesis the statement omits.

ALG-U5-Q17MCQmedium

An undirected graph on A, B, C, D has edges AB 1, BC 1, AC 1, CD 1, BD 3, AD 4. How many distinct minimum spanning trees does it have?

  1. 1
  2. 2
  3. 3
  4. 4
Show answer & solution

Detailed solution

Concept. A minimum spanning tree need not be unique when weights repeat. Any spanning tree whose edges can be exchanged one at a time with equal-weight alternatives without breaking the cut and cycle conditions is also a minimum spanning tree.

Step by step.

  1. The four weight-1 edges are AB, BC, AC, CD. A spanning tree of four vertices needs three edges, so the minimum possible total weight is 3.
  2. D has three incident edges: CD 1, BD 3, AD 4. A tree of weight 3 must reach D with the edge of weight 1, so CD is in every minimum tree.
  3. The remaining two edges must span A, B, C at total weight 2, so both must be weight-1 edges from the triangle {AB, BC, AC}.
  4. Any two of the three triangle edges form a spanning tree of the triangle, giving {AB, BC}, {AB, AC} and {BC, AC} — three trees, each of total weight 3.

Answer: 3 — option (C).

Common misconception. Answering 1 assumes that equal weights still give a unique tree. Answering 4 counts all three triangle edges as a choice, but a spanning tree of four vertices has exactly three edges, so AB, BC, AC together would close a cycle and is not a tree.

ALG-U5-Q18MSQmedium

Which of the following statements about minimum spanning trees are TRUE?

  1. If all edge weights of a connected graph are distinct, its minimum spanning tree is unique.
  2. When all edge weights are distinct, Prim's algorithm returns the same tree whichever vertex it starts from.
  3. A minimum spanning tree contains, for every cycle of the graph, the heaviest edge of that cycle.
  4. On a connected graph with V vertices and E edges, Prim's algorithm with a binary heap runs in O(E log V).
Show answer & solution

Detailed solution

Concept. Distinct weights force uniqueness, which in turn makes every correct MST algorithm agree; the cycle property forbids the heaviest edge of a cycle from being forced into the tree; and a binary heap bounds Prim's cost by the number of heap operations.

Step by step.

  1. (A) TRUE. Suppose two different minimum trees existed. Their symmetric difference contains a cycle on which the two trees alternate; swapping along it would exchange one edge for a strictly lighter one, contradicting minimality.
  2. (B) TRUE. Uniqueness makes the tree independent of the algorithm and of the start vertex.
  3. (C) FALSE. The cycle property says the heaviest edge of a cycle can always be excluded without losing minimality — it is the edge an MST avoids, not the one it must contain.
  4. (D) TRUE. Every edge enters and leaves the heap at most once, so there are O(E) heap operations at O(log V) each, plus the O(V) extraction phase.

Answer: (A), (B) and (D) are TRUE; (C) is FALSE.

Common misconception. (C) inverts the cycle property, which is the single most common MST error. Note also that (B) depends on (A): with repeated weights, two start vertices can legitimately return different minimum trees, so (B) must be read with its hypothesis attached.

ALG-U5-Q19NATmedium

An undirected graph on A–E has edges AB 2, BC −3, CD 4, DE 1, AE 5, BD 6, AC 7. What is the total weight of a minimum spanning tree?

Show answer & solution

Detailed solution

Concept. Both Prim's and Kruskal's algorithms rely only on comparisons between edge weights, so negative weights are handled exactly as positive ones. (Negative cycles matter for shortest paths, not for spanning trees.)

Step by step.

  1. Sort the edges: BC −3, DE 1, AB 2, CD 4, AE 5, BD 6, AC 7.
  2. Take BC −3. Take DE 1.
  3. Take AB 2, which links A to {B, C}.
  4. Take CD 4, which links {A, B, C} to {D, E}.
  5. Five vertices need four edges, and all five are now connected; the remaining candidates AE 5, BD 6, AC 7 would close cycles.
  6. Total −3 + 1 + 2 + 4 = 4.

Answer: 4.

Common misconception. The two standard errors are to refuse the negative edge, or to reach for Bellman–Ford reasoning and conclude that negative weights break the greedy choice. Also note that the MST is not the shortest-path tree: the distance from A to C in the tree is 2 − 3 = −1 along the tree, but the tree is chosen for total weight, not for any single path.

ALG-U5-Q20MCQeasy

A weighted undirected graph on vertices A–F has edges AB 4, AD 1, BC 2, BE 3, CF 5, DE 6, EF 7, BD 8, CE 9. Kruskal's algorithm processes the edges in increasing order of weight. Which edge is the first to be rejected because its endpoints are already connected?

  1. BD (weight 8)
  2. DE (weight 6)
  3. EF (weight 7)
  4. CE (weight 9)
Show answer & solution

Detailed solution

Concept. Kruskal's algorithm accepts an edge only when its endpoints lie in different components of the forest built so far; the union–find structure answers that question and performs the merge.

Step by step.

  1. Process AD 1: components {A, D}.
  2. BC 2: {A, D} and {B, C}.
  3. BE 3: {A, D} and {B, C, E}.
  4. AB 4: merges them into {A, B, C, D, E}.
  5. CF 5: F joins, so all six vertices are connected and the tree is complete.
  6. DE 6 is next: D and E are both already in the single component, so it is rejected.

Answer: DE with weight 6 — option (B).

Common misconception. The answer is not the heaviest edge, nor the first edge that would close a triangle. The forest is already spanning after five edges, so the very next edge in sorted order is rejected; every later edge is rejected too, which is why "the first rejected" and "the first edge after the tree is complete" coincide here.

ALG-U5-Q21MCQeasy

A disjoint-set forest stores parent pointers with parent[1] = 1, parent[2] = 1, parent[3] = 2 and parent[4] = 3. A find on element 4 is executed with full path compression. How many entries of the parent array change value?

  1. 2
  2. 0
  3. 1
  4. 3
Show answer & solution

Detailed solution

Concept. Path compression makes every node on the path from the queried element to the root point directly at the root. Nodes that already point at the root are left alone, so the count of changed entries is the number of non-root nodes on the path minus those already one hop from the root.

Step by step.

  1. Walking up from 4: 4 → 3 → 2 → 1, and parent[1] = 1, so the root is 1.
  2. The path is 4, 3, 2 and all three should point at 1 afterwards.
  3. parent[2] = 1 already, so it does not change.
  4. parent[3] changes from 2 to 1; parent[4] changes from 3 to 1.
  5. Two entries change.

Answer: 2 — option (A).

Common misconception. Counting three counts the node 2, whose pointer was already correct. Counting one counts only the queried node, which is what a lazy "compress just the argument" implementation does — that is not path compression.

ALG-U5-Q22MCQeasy

Which of the following statements about Kruskal's algorithm is TRUE?

  1. It must rebuild the forest with a fresh depth-first search after every union, and that dominates its running time.
  2. With union by rank and path compression, each union or find costs Θ(log E) in the worst case.
  3. It requires the graph to be connected, because otherwise it never terminates.
  4. Its running time is dominated by sorting the edges, giving O(E log E) for a graph with E edges.
Show answer & solution

Detailed solution

Concept. Kruskal's algorithm is sorting plus O(E) union–find operations. Sorting costs O(E log E) and the disjoint-set operations cost O(E α(V)), so sorting dominates.

Step by step.

  1. Sort the E edges: O(E log E).
  2. Scan the sorted list once, calling find twice and union at most once per edge: O(E α(V)) with union by rank and path compression.
  3. Total O(E log E), which is the same order as O(E log V) because E ≤ V² and log E ≤ 2 log V.
  4. (A) is the naive cycle test, which costs a search per edge; (B) contradicts the inverse-Ackermann bound; (C) is false — on a disconnected graph the algorithm simply returns a spanning forest.

Answer: Sorting dominates, so O(E log E) — option (D).

Common misconception. (B) is the trap for anyone who remembers "logarithmic" but not the inverse Ackermann function: with both heuristics the amortised cost per operation is O(α(n)), which is effectively constant. (C) confuses "no spanning tree exists" with "the algorithm misbehaves".

ALG-U5-Q23MSQhard

Which of the following statements about Kruskal's algorithm and the disjoint-set structure are TRUE?

  1. On a connected graph with V vertices, Kruskal's algorithm performs exactly V − 1 successful unions.
  2. If the edges are processed in non-decreasing weight order and ties are broken arbitrarily, the resulting tree is always a minimum spanning tree, though not necessarily the same one on every run.
  3. Union by rank without path compression gives amortised O(log n) per operation.
  4. Kruskal's algorithm detects a cycle by running a depth-first search on the forest built so far, and the total cost is still O(E log E).
Show answer & solution

Detailed solution

Concept. Kruskal's correctness is independent of tie-breaking; its efficiency depends on the disjoint-set structure, whose guarantees are a union-by-rank height bound and an amortised inverse-Ackermann cost once path compression is added.

Step by step.

  1. (A) TRUE. A successful union merges two components, and the number of components falls from V to 1; every merge adds one tree edge, so there are exactly V − 1.
  2. (B) TRUE. The greedy choice is safe by the cut property whatever the tie-break; only the identity of the tree can vary.
  3. (C) TRUE. Union by rank keeps every tree of height at most ⌊log₂ n⌋, so a find walks at most logarithmically many pointers, and each union is O(1) after two finds.
  4. (D) FALSE. A depth-first cycle test costs O(V) per edge, so the total would be O(E·V), which is worse than O(E log E) for dense graphs.

Answer: (A), (B) and (C) are TRUE; (D) is FALSE.

Common misconception. (D) is tempting because it really is a correct algorithm — the false part is the complexity claim. (C) is often denied on the grounds that "only path compression helps", but union by rank alone already bounds the height, which is what the per-operation cost follows from.

ALG-U5-Q24MSQmedium

Which of the following statements about the disjoint-set (union–find) structure are TRUE?

  1. Union by size guarantees that the height of any tree is at most ⌊log₂ n⌋.
  2. Path compression rewrites the parent pointer of every node on the path from the queried element to the root.
  3. With both union by rank and path compression, a sequence of m operations costs O(m α(n)).
  4. The rank of a node increases every time that node is passed to find.
Show answer & solution

Detailed solution

Concept. Union by size or rank bounds tree height; path compression flattens the path walked by a find; together they give the inverse-Ackermann amortised bound. Neither heuristic changes the number of elements in a set, and only union changes a rank.

Step by step.

  1. (A) TRUE. Attaching the smaller tree under the larger root means a node's tree size at least doubles each time its depth increases, so the depth is at most log₂ n.
  2. (B) TRUE. That is the definition of full path compression: every node on the path is re-pointed at the root.
  3. (C) TRUE. This is the classical Tarjan bound; α(n) ≤ 4 for any conceivable n, so the cost is effectively linear.
  4. (D) FALSE. find never changes a rank. A rank increases only when a root is attached under another root of equal rank during a union.

Answer: (A), (B) and (C) are TRUE; (D) is FALSE.

Common misconception. (D) confuses rank with the parent pointer: path compression does change parent pointers during a find, but rank is a separate field that records the height bound and is updated only by unions. Answering (A) as false is also common, because people remember the bound as "log n" without the floor or the base.

Concept map used to build the questions

  • Levels and depths. BFS labels a vertex with the number of edges on a shortest path from the source, so a level count is a distance question and a distance sum is a level-structure question. DFS instead records a discovery and a finish time per vertex, and its forest has one tree per run of the outer loop.
  • Edge classification. The colour of the target decides the type: white gives a tree edge, grey a back edge, and a finished target is forward when it is a descendant and cross otherwise. In an undirected graph only tree and back edges exist, and a non-tree edge never spans two levels of a BFS tree.
  • Partial orders. A topological ordering is a linear extension of reachability: it exists exactly for DAGs, it is unique exactly when the DAG carries a Hamiltonian path, and its count is the number of ways the ready set can be ordered — which is what Kahn’s queue versus a priority queue is really choosing between.
  • The cut property. A lightest edge across a cut is safe for some minimum spanning tree. Prim applies it to the cut (tree, rest) and grows one tree; Kruskal applies it to the cut induced by the current components and merges many. The cycle property is its mirror image: the heaviest edge of a cycle is in no minimum spanning tree.
  • Disjoint sets. Union by rank or size bounds the height by a logarithm because a node’s tree at least doubles whenever its depth grows; path compression then flattens the paths a find walks. Together they give the inverse-Ackermann amortised cost that makes Kruskal’s total the cost of sorting.
  • Connections. BFS levels are the unit-weight case of Dijkstra’s distance labels; DFS finish times drive both topological sort and strongly connected components; the union–find structure reappears in cycle detection and offline connectivity; and the uniqueness argument for minimum spanning trees is the same exchange argument used for matroids.
