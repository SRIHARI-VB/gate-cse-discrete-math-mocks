CD-U1-Q01MCQeasy

Separating lexical analysis from syntax analysis is standard compiler practice. Which of the following is NOT one of the standard reasons for the separation?

  1. It simplifies the overall design of the compiler.
  2. It allows specialised, efficient techniques for buffering and scanning the source text.
  3. It improves portability, because the peculiarities of the input alphabet are isolated in one place.
  4. It removes all ambiguity from the grammar before the parser sees it.
Show answer & solution

Detailed solution

Concept. The three classical reasons for a separate lexical phase are simplicity of design, compiler efficiency (specialised buffering and scanning) and compiler portability (the input-alphabet peculiarities are confined to the lexer).

Step by step.

  1. Options (A), (B) and (C) are exactly those three reasons.
  2. Ambiguity is a property of the grammar, decided by the parser; no scanner can change the set of parse trees a grammar admits.
  3. A lexer can reject an ill-formed lexeme, but it cannot decide whether the grammar is ambiguous.

Final answer. Option (D) — removing ambiguity is not a reason for separating lexical analysis.

Common misconception. Believing that the lexer "resolves" grammar-level conflicts. The lexer classifies characters into tokens; ambiguity of the grammar survives it untouched.

CD-U1-Q02MCQeasy

A scanner uses the maximal-munch (longest-match) rule and has token classes for identifiers, ++, + and =. For the input a+++b, which token sequence does it return?

  1. a  ++  +  b
  2. a  +  ++  b
  3. a  +  +  +  b
  4. a  +++  b
Show answer & solution

Detailed solution

Concept. Maximal munch: at every position the scanner takes the longest prefix that is a valid token; only when several rules match the same longest prefix does rule order break the tie.

Step by step.

  1. Position 1: a starts an identifier; an identifier cannot contain +, so the token is a.
  2. Position 2: the characters are +++. The longest valid token here is ++ (two characters), so it is returned.
  3. Position 4: the single + remains and is returned as +.
  4. Position 5: b is an identifier.
  5. Result: a, ++, +, b.

Final answer. Option (A): a ++ + b.

Common misconception. Splitting greedily as + + + (option C) ignores maximal munch, and treating +++ as one token (option D) invents a token class that does not exist.

CD-U1-Q03MCQeasy

For the source line int sum = 0; a conventional lexer inserts how many new entries into the symbol table while scanning it?

  1. 0
  2. 1
  3. 2
  4. 3
Show answer & solution

Detailed solution

Concept. The symbol table holds information about identifiers. Keywords are recognised by the lexer as fixed token classes and are not entered as identifiers.

Step by step.

  1. int — a keyword: returned as the token class INT, no symbol-table entry.
  2. sum — an identifier: one entry is created (its lexeme, type, later its scope and address).
  3. = and ; — punctuation tokens, no entry.
  4. 0 — a constant; constants are usually kept in a separate literal/constant table, not the symbol table.
  5. Total new symbol-table entries: 1.

Final answer. Option (B) — exactly one entry, for sum.

Common misconception. Counting the keyword int (giving 2) or the constant 0 (giving 3). Keywords are not identifiers, and constants belong to a separate table.

CD-U1-Q04MCQmedium

Which of the following decisions cannot be made by the lexical analyser alone?

  1. Whether a sequence of characters is a well-formed identifier of the language.
  2. Whether an identifier used in an expression has been declared earlier in the program.
  3. Whether a sequence of characters forms a valid numeric literal of the language.
  4. Whether a comment opened near the end of the file is still unterminated.
Show answer & solution

Detailed solution

Concept. A lexer classifies characters into tokens using regular expressions. Anything that needs information gathered across the whole program — such as which identifiers are declared, and in which scope — is outside the regular-power of a scanner and belongs to semantic analysis with a symbol table.

Step by step.

  1. Well-formedness of an identifier (A) is exactly a regular-expression test, so the lexer decides it.
  2. A valid numeric literal (C) is again a regular language; the lexer decides it.
  3. An unterminated comment (D) is detected while matching the comment pattern at end of file — a lexical error.
  4. Declaration-before-use (B) needs a symbol table filled in program order and a notion of scope; a scanner cannot answer it, and a one-token lookahead certainly cannot.

Final answer. Option (B) — declaration checking is a semantic (parser/semantic-analyser) task, not a lexical one.

Common misconception. Assuming that because the lexer fills a symbol table it can also check declarations. The lexer records identifiers; it does not reason about their declarations.

CD-U1-Q13MCQhard

A scanner lists its rules in this order: (1) [a-z]+ → return ID; (2) if → return IF. In a Lex/Flex-style scanner, what happens on the input if?

  1. IF is returned, because keyword rules automatically outrank identifier rules.
  2. ID is returned, because both rules match the same two-character lexeme and the earlier rule wins the tie, so rule (2) never fires.
  3. A lexical error is reported, because two rules match the same text.
  4. ID is returned for if but IF for a longer word such as iffy.
Show answer & solution

Detailed solution

Concept. Rule selection is two-stage: (i) choose the longest match among all rules; (ii) if several rules match that same longest lexeme, the rule written earliest wins.

Step by step.

  1. Both rules match exactly two characters of if — neither match is longer.
  2. The tie is therefore broken by rule order, and rule (1) is earlier.
  3. So the scanner returns ID and rule (2) is dead code: no input can ever make it fire.
  4. The correct specification lists the keyword rule before the identifier rule.

Final answer. Option (B).

Common misconception. Assuming that keyword recognition is automatic, or that a "more specific" pattern outranks a more general one. Lex has no specificity rule — only longest match, then earliest rule. Option (D) is also wrong because iffy matches only [a-z]+ (longer than if).

CD-U1-Q16MSQeasy

Which of the following statements about lexemes and tokens are true?

  1. Two different lexemes can belong to the same token class.
  2. A token is a pair: a token name (an abstract class) and an optional attribute value; a lexeme is the concrete string matched.
  3. Every token returned for a keyword must carry an attribute value.
  4. A correct scanner assigns each lexeme to exactly one token class, because longest-match and rule-priority resolve any overlap.
Show answer & solution

Detailed solution

Concept. A token class is a set of lexemes; the lexer returns a token name plus, when needed, an attribute that distinguishes the members of that class.

Step by step.

  1. (A) True: count1 and total are different lexemes of the same class id.
  2. (B) True: that is the standard definition — e.g. <id, pointer to symbol-table entry>.
  3. (C) False: keywords and punctuation need no attribute; the token name alone identifies them.
  4. (D) True: the two conventions (longest match, then earliest rule) make the scanner deterministic, so a lexeme such as if cannot be both a keyword and an identifier.

Final answer. Options (A), (B) and (D).

Common misconception. Statement (C) is the trap: attributes exist to distinguish members of a class (which identifier? which constant?). A keyword has no members to distinguish.

CD-U1-Q20MSQmedium

Which of the following statements about the lexer–parser interface are true?

  1. A lexer must produce the complete token stream for a file before the parser can begin.
  2. A token may carry an attribute value, for example a pointer to the symbol-table entry of an identifier.
  3. Deciding whether an identifier has been declared before its use is part of lexical analysis.
  4. In a single-pass design the parser may keep one token of lookahead, which amounts to pushing a token back to the lexer.
Show answer & solution

Detailed solution

Concept. The parser normally pulls tokens on demand through a procedure such as getNextToken(), and the two phases communicate through tokens with attributes.

Step by step.

  1. (A) False: production compilers are demand-driven; buffering the whole file as tokens wastes memory and delays error reporting.
  2. (B) True: <id, p>, where p points at the identifier's symbol-table entry, is the standard example.
  3. (C) False: declaration checking needs the symbol table built across statements — a semantic task.
  4. (D) True: a one-token pushback is a common way to give the parser the lookahead it needs.

Final answer. Options (B) and (D).

Common misconception. Statement (A) is the trap: it describes a batch design nobody uses, and it would make single-pass compilation impossible.

CD-U1-Q21NATeasy

How many tokens does a C lexer return for the input line total = count1 + 42;? Count keywords, identifiers, operators, constants and punctuation as one token each, and ignore whitespace.

Show answer & solution

Detailed solution

Concept. Every lexeme that is not whitespace or a comment becomes exactly one token; whitespace between tokens is discarded by the scanner.

Step by step.

  1. total — identifier (1)
  2. = — assignment operator (2)
  3. count1 — identifier (3)
  4. + — additive operator (4)
  5. 42 — integer constant (5)
  6. ; — punctuation (6)
  7. Whitespace contributes no token.

Final answer. 6 tokens.

Common misconception. Counting the four spaces as tokens, or merging count1 into one token with +. Whitespace is skipped, and each maximal lexeme is a separate token.

CD-U1-Q26MCQeasy

Which one of the following is not passed from the lexical analyser to the syntax analyser as a token?

  1. A keyword such as while
  2. An identifier such as total
  3. A comment such as /* note */
  4. A relational operator such as <=
Show answer & solution

Detailed solution

Concept. A token is the pair (token name, attribute value). White space and comments are recognised by the scanner only so that they can be discarded; they never reach the parser.

Step by step.

  1. The scanner reads characters and groups them into lexemes.
  2. Each lexeme that matches a token pattern is returned as a token name with an optional attribute value.
  3. Comments and blank space have patterns too, but their only purpose is to be skipped.
  4. So a comment is consumed by the lexer and is not a token.

Final answer. Option (C) — a comment is not a token.

Common misconception. A comment is made of characters and is matched by a regular expression, so it feels like a token. Being recognised by the lexer and being handed to the parser are different things.

CD-U1-Q27MCQeasy

Three ideas are involved in scanning: a token, a pattern and a lexeme. A lexeme is

  1. a regular expression that describes every string of a token class
  2. the actual sequence of characters in the source text that matches the pattern of a token
  3. the internal integer code that a compiler assigns to a token class
  4. the list of attributes kept for an identifier in the symbol table
Show answer & solution

Detailed solution

Concept. Pattern, lexeme and token form a three-level hierarchy: the pattern is the description, the lexeme is the concrete string, and the token is the abstract class handed to the parser.

Step by step.

  1. Pattern: the form that the lexemes of a token may take, written as a regular expression.
  2. Lexeme: a sequence of characters in the source program that matches a pattern.
  3. Token: the abstract class returned to the parser.
  4. Hence a lexeme is the actual character sequence.

Final answer. Option (B).

Common misconception. Option (A) is the pattern and option (C) is the token code. Collapsing the three levels is the usual mistake.

CD-U1-Q28MCQmedium

The scanner returns a pair (token name, attribute value). For an identifier token the attribute value is normally

  1. the token name repeated, so that the parser can compare names
  2. a pointer to the entry for that lexeme in the symbol table
  3. the line number on which the identifier occurs
  4. empty, because identifiers carry no information
Show answer & solution

Detailed solution

Concept. Attribute values distinguish different lexemes that share one token name. Every identifier maps to the token name id, so the attribute must identify which identifier it is.

Step by step.

  1. All identifiers share the token name id.
  2. Without an attribute, count and total would be indistinguishable to the parser.
  3. The scanner therefore returns a pointer to the symbol-table entry holding the lexeme and its attributes.
  4. The line number is used for diagnostics and is not the attribute of the identifier.

Final answer. Option (B).

Common misconception. Thinking the attribute is the character string itself. Implementations may store the string in the symbol table and pass a pointer; the attribute is the symbol-table entry, not the token name.

CD-U1-Q29MCQmedium

The C statement x = -1; is scanned with maximal munch. How many tokens does the scanner produce? Treat -= as a valid C operator, and ignore white space.

  1. 3
  2. 4
  3. 5
  4. 6
Show answer & solution

Detailed solution

Concept. Maximal munch takes the longest prefix that matches some pattern. A compound operator exists only if it really is a token of the language, so =- cannot be formed.

Step by step.

  1. At x the identifier pattern matches just x, giving token 1.
  2. At = the scanner tries the two-character candidate =-; no such operator exists, so the one-character = is taken. Token 2.
  3. The - is then the unary minus operator. Token 3.
  4. The constant 1 is token 4 and the ; is token 5.
  5. Total: x, =, -, 1, ; — five tokens.

Final answer. Option (C) — 5 tokens.

Common misconception. Answering 4 by treating =- as one operator, or 3 by assuming the unary minus belongs to the constant. The minus sign is a token in its own right.

CD-U1-Q31MSQhard

Which of the following tasks belong to the lexical analyser? (Select all that apply.)

  1. Stripping comments and white space before the tokens reach the parser.
  2. Entering each new identifier into the symbol table.
  3. Deciding whether the grammar of the language is ambiguous.
  4. Recording the line number so that later phases can report positions.
  5. Performing type checking on expressions.
Show answer & solution

Detailed solution

Concept. The scanner does character-level work: it groups characters into lexemes, discards noise, records positions and maintains the symbol table. Grammar-level and type-level decisions belong to later phases.

Step by step.

  1. Stripping comments and white space: a scanner task, since only the scanner sees raw characters.
  2. Inserting identifiers into the symbol table: done while scanning, so each identifier is entered once.
  3. Deciding whether the grammar is ambiguous: a property of the grammar, decided by the parser designer — no scanner can affect it.
  4. Recording line numbers: the scanner tracks yylineno for error messages.
  5. Type checking: a semantic-analysis task, performed on the syntax tree.

Final answer. Options (A), (B) and (D).

Common misconception. Assuming the scanner 'resolves' ambiguity. Ambiguity is a property of the grammar; separating phases cannot remove it.

Which regular expression denotes exactly the set of identifiers that begin with a letter and continue with letters or digits (one or more characters in all)?

  1. [A-Za-z][A-Za-z0-9]*
  2. [A-Za-z]*[A-Za-z0-9]*
  3. [A-Za-z0-9]+
  4. [A-Za-z][A-Za-z]*
Show answer & solution

Detailed solution

Concept. The first character must come from the letter class and the remaining characters from the letter-or-digit class, with zero or more remaining characters.

Step by step.

  1. (A) forces one letter, then any number of letters or digits — exactly the required language.
  2. (B) lets the first part match the empty string, so the digit part can supply a leading digit (9x is matched); it also matches the empty string.
  3. (C) allows an identifier to start with a digit (1abc).
  4. (D) forbids digits anywhere after the first character.

Final answer. Option (A).

Common misconception. Option (B) is the classic trap: writing two stars in sequence does not impose a constraint on the first character, because the first star may match nothing.

CD-U1-Q06MCQmedium

How many states does the minimal DFA accepting the language denoted by (a|b)*abb have?

  1. 3
  2. 4
  3. 5
  4. 8
Show answer & solution

Detailed solution

Concept. A DFA for "ends with abb" only has to remember how much of the pattern abb is currently matched as a suffix of the input read so far.

Step by step.

  1. State 0: nothing matched (no suffix of abb).
  2. State 1: the input ends in a.
  3. State 2: the input ends in ab.
  4. State 3 (accepting): the input ends in abb.
  5. Transitions: on b state 0 stays in 0; on a state 0 goes to 1; state 2 on b goes to 3, on a back to 1; state 3 on b stays in 3, on a goes to 1.
  6. All four states are reachable and pairwise distinguishable, so the minimal DFA has 4 states.

Final answer. Option (B) — 4 states.

Common misconception. Answering 8 by applying the 2ⁿ subset-construction bound. That bound is a worst case for the NFA of the expression; the minimal DFA for this language needs only 4 states.

CD-U1-Q07MCQhard

Which of the following regular expressions does not denote the set of all strings over {a, b}?

  1. (a + b)*
  2. (a* b*)*
  3. (b* a*)*
  4. (a b*)*
Show answer & solution

Detailed solution

Concept. Two expressions denote the same language only if each can generate every string of the other. Test a string that starts with the "wrong" symbol.

Step by step.

  1. (A) is Σ* by definition.
  2. (B) (a*b*)*: any string can be cut into maximal blocks of a's and b's, so it generates all of Σ*.
  3. (C) (b*a*)*: similarly, cut the string into maximal blocks of b's followed by a's.
  4. (D) (ab*)*: every iteration starts with an a, so every non-empty generated string begins with a. The string ba is not generated.
  5. Hence (D) is not Σ*.

Final answer. Option (D).

Common misconception. Assuming that any star applied to a concatenation equals Σ*. Always test a short string that begins with the symbol the first factor does not allow.

CD-U1-Q15MCQhard

A scanner has the token classes INT = [0-9]+, FLOAT = [0-9]+\.[0-9]+ and DOT = \.. On the input 3.14 the scanner returns

  1. INT 3, then DOT ., then INT 14
  2. FLOAT 3.14
  3. FLOAT 3.1, then INT 4
  4. a lexical error, because 3.14 matches two rules
Show answer & solution

Detailed solution

Concept. Rule priority is decided by match length first. INT can match only the first character; FLOAT can match all four; the longest match therefore wins, and rule order is irrelevant here.

Step by step.

  1. At position 1, INT matches 3 (length 1).
  2. At the same position FLOAT matches 3.14 (length 4).
  3. Longest match wins: FLOAT 3.14 is returned as one token.
  4. The DOT rule is never consulted, because a longer match already exists.

Final answer. Option (B) — a single FLOAT token.

Common misconception. Assuming the first matching rule wins (option A). Order only breaks ties between matches of equal length; here the lengths differ, so longest match decides.

CD-U1-Q17MSQmedium

Which of the following languages can be recognised by a DFA, and hence by a Lex/Flex-generated lexer?

  1. The set of strings over {a, b} that end in ab.
  2. The set of strings over {a, b} that contain an equal number of a's and b's.
  3. The set of strings over {a, b} of the form aⁿbⁿ, n ≥ 0.
  4. The set of valid C integer literals (decimal, octal and hexadecimal).
Show answer & solution

Detailed solution

Concept. A scanner can recognise exactly the regular languages. A language is regular iff some finite automaton accepts it; languages needing unbounded counting are not regular (pumping lemma).

Step by step.

  1. (A) Regular: a three-state automaton remembers whether the last two symbols were ab.
  2. (B) Not regular: it needs to count the difference between the number of a's and b's, which is unbounded.
  3. (C) Not regular: it needs to count the a's and compare with the b's.
  4. (D) Regular: the set of syntactically valid literals is described by a regular expression such as 0[xX][0-9a-fA-F]+ | 0[0-7]* | [1-9][0-9]*.

Final answer. Options (A) and (D).

Common misconception. Believing a larger buffer or a bigger automaton can count. No finite automaton can compare two unbounded counts — that is exactly what the pumping lemma rules out.

  4. Merging can only reduce the node count, so (C) is wrong, and DAGs represent whole basic blocks including assignments, so (D) is wrong.

Final answer. Option (A).

Common misconception. Believing the DAG is only a drawing convention. Sharing is the data structure that lets the compiler see that the second occurrence needs no new computation.

CD-U4-Q16MCQeasy

Which optimisation is exposed directly by building a DAG for a basic block?

  1. loop unrolling
  2. register allocation
  3. strength reduction
  4. common subexpression elimination
Show answer & solution

Detailed solution

Concept. Two occurrences of the same expression map to the same node in the DAG. Every node with more than one parent is therefore a common subexpression, computed once and reused.

Step by step.

  1. Build the DAG for the block, creating one node per distinct value.
  2. Read the DAG back out: a node with several parents is emitted once, and its later uses refer to the earlier result.
  3. Dead-code elimination is also available from the DAG — nodes with no live value are dropped — but the optimisation the construction exposes directly is common subexpression elimination.
  4. Loop unrolling, register allocation and strength reduction are loop-level or machine-level transformations; a single basic block contains no loop to unroll.

Final answer. Option (D).

Common misconception. Expecting the DAG to reorder code. It only merges equal values; the instruction order still has to be recovered from the graph when the block is emitted.

Show answer & solution

Detailed solution

Concept. Build the DAG bottom-up, creating a leaf once per distinct variable and merging any two interior nodes with the same operator and the same children. The two subtractions b - c are identical, so they share one node.

  1. Leaves: a, a, b, c, b, c, d collapse to the four distinct leaves a, b, c, d.

  3. n2 = a * n1.
  4. n3 = a + n2.
  5. n4 = n1 * d.
  6. n5 = n3 + n4, the root.
  7. Interior nodes n1 to n5 = 5; leaves = 4; total = 9.

CD-U4-Q18MCQmedium

In a DAG built for a basic block, an interior node labelled + with two children represents:

  1. two variables that are added somewhere in the block.
  2. the value obtained by applying + to the values of its children, a node shared by every use of that value.
  3. an instruction that must be executed twice.
  4. an operand whose value is not known at compile time.
Show answer & solution

Detailed solution

Concept. Each node of the DAG denotes a value. A leaf denotes the value of a variable; an interior node denotes the value produced by applying its operator to the values of its children.

Step by step.

  1. The label names the operator, the children name the operands, and the node names the result.
  2. Because nodes are merged on identical operator and identical children, a node with several parents is a value computed once and used several times.
  3. Option (C) confuses the value with the instruction: a shared node means the opposite of executing twice.
  4. Option (D) confuses a node with an unknown: every node in the DAG of a basic block is a value the block computes.

CD-U4-Q19MSQmedium

Which of the following statements about DAGs for basic blocks are TRUE? (Select all that apply.)

  1. A DAG exposes the common subexpressions of a basic block.
  2. A node whose value is never used can be removed from the DAG, which is dead-code elimination.
  3. Every syntax tree is a DAG.
  4. A DAG never has more nodes than the syntax tree of the same expression.
  5. A DAG for an expression can always be converted back into a unique syntax tree.
Show answer & solution

Detailed solution

Concept. The DAG is obtained from the syntax tree by merging equal subexpressions. Merging never creates a node and never changes a value, so the DAG is a quotient of the tree.

Step by step.

  1. (A) is the point of the construction: a node with several parents is a common subexpression.
  2. (B) is true. A node with no parent outside the DAG and no live variable attached computes a value nobody reads; deleting it, and then its orphaned children, is dead-code elimination.
  3. (C) is true: a tree is an acyclic directed graph in which every node has at most one parent.
  4. (D) is true because the DAG is built by merging nodes of the tree; the node count can only fall.
  5. (E) is false. After merging, the information about which occurrence came first is gone: (a + b) * (a + b) and a block computing a + b once and using it twice give the same DAG, and a shared node can be expanded in several different tree shapes.

Final answer. Options (A), (B), (C) and (D).

Common misconception. Believing the DAG is a lossless replacement for the syntax tree. It preserves values, not occurrences, so a unique tree cannot be recovered from it.

CD-U4-Q20MCQeasy

Local value numbering finds common subexpressions in a basic block by:

  1. sorting the instructions of the block by operator.
  2. counting how many times each variable is assigned.
  3. giving the same number to two expressions that have the same operator and the same numbered operands.
  4. building the loop-nesting structure of the block.
Show answer & solution

Detailed solution

Concept. Value numbering walks the block in order, assigning a number to each value. A leaf variable gets a number; an expression gets a number determined by its operator and the numbers of its operands. Two expressions with the same key are the same value.

Step by step.

  1. Read the block left to right, keeping a table from keys to numbers.
  2. For t1 = b * c the key is (*, #b, #c); it is new, so it receives a fresh number.
  3. When a later instruction has the same key, it receives the same number, so it is a redundant computation and can be replaced by a copy of the earlier result.
  4. Sorting instructions, counting assignments and analysing loop nesting are different analyses and none of them identifies equal expressions.

Final answer. Option (C).

Common misconception. Comparing expressions as text. Value numbering compares the values of operands, so it also catches t2 = x * y when x was previously copied from b and y from c.

When a parse tree is condensed into a syntax tree, which one of the following is the result?

Detailed solution

Concept. A syntax tree is a condensed parse tree: nodes whose productions have a single symbol on the right, and punctuation such as parentheses, are removed because they carry no value.

  1. Two interior nodes are merged exactly when they carry the same operator and the same ordered list of children.
  2. A leaf labelled with a variable may have more than one parent.
  3. Every interior node of the DAG has exactly one parent.
  4. The DAG can be built incrementally, one statement at a time, reusing an existing node whenever an identical one is already present.

Detailed solution

Concept. The DAG is built by a value-numbering style pass: each variable and each operator application is given a number, and a repeated number means the node already exists.

Step by step.

  1. (A) is true and is the merge rule; the order of children matters, since subtraction and division are not commutative.
  2. (B) is true — a variable used in several statements has one leaf with several parents, which is exactly the sharing the DAG records.

  5. (E) is false. No separate syntax tree is needed; nodes are created as each statement is processed.

CD-U4-Q43MCQmedium

Which statement relating the syntax tree and the DAG of the same expression is TRUE?

  1. The DAG always has strictly fewer nodes than the syntax tree.
  2. The DAG never has more nodes than the syntax tree, and has fewer exactly when some subexpression occurs more than once.
  3. The DAG and the syntax tree always have the same number of nodes.
  4. The DAG may have more nodes, because it records sharing with extra nodes.
Show answer & solution

Detailed solution

Concept. A DAG is obtained from a syntax tree by merging nodes that denote the same value, so it is at most as large as the tree.

Step by step.

  1. Every node of the DAG corresponds to at least one node of the syntax tree, so the DAG has no more nodes.
  2. If no subexpression repeats, nothing can be merged and the two have the same size — which rules out option (A).
  3. Sharing is recorded by extra edges, never by extra nodes, which rules out option (D).

Final answer. Option (B).

CD-U4-Q44MCQhard

A DAG is built for the basic block d = a + b; e = a + b; f = d + e. How many interior nodes does the DAG contain?

  1. 1
  2. 2
  3. 3
  4. 4
Show answer & solution

Detailed solution

Concept. Each statement adds at most one interior node, and an identical node is reused rather than created.

Step by step.

  1. d = a + b creates n1 = +(a, b); d is attached to n1.
  2. e = a + b finds the identical node n1 already present, so no node is created; e is attached to the same n1.
  3. f = d + e becomes +(n1, n1), a new node n2, because its children are node numbers, not the operands a and b.
  4. Interior nodes: n1 and n2 — two. Adding the three leaves a, b and the variable labels gives the full node count, but only two are interior.

Final answer. Option (B) — 2.

  2. that an array subscript is within bounds at run time

Show answer & solution

Detailed solution

Concept. Static checks are decided from the program text alone, before execution; dynamic checks need the run-time values and are therefore inserted as code or left to the run-time system.

Step by step.

  4. Whether a pointer is null depends on the execution path, so it is a run-time property.

Final answer. Option (A).

Which of the following statements about type checking are TRUE? (Select all that apply.)

  1. Type checking can be done statically, before the program runs, or dynamically, while it runs.
  2. A sound type system guarantees that a well-typed program cannot suffer a run-time type error.
  3. A complete type checker accepts every program that cannot suffer a run-time type error.
  4. A coercion is an implicit conversion inserted by the compiler to make the types of two operands agree.
  5. A static type checker rejects every program that could suffer a run-time type error.
Show answer & solution

Detailed solution

Concept. Soundness and completeness are the two directions of correctness. Sound: nothing accepted is wrong. Complete: nothing right is rejected. They are independent properties, and a static checker that is both sound and complete cannot exist for a Turing-complete language.

Step by step.

  1. (A) is true: a compiler checks types before execution, and a language may also check them at run time, as Lisp and Python do.
  2. (B) is the definition of soundness.
  3. (C) is the definition of completeness.
  4. (D) is the standard meaning of coercion, as when an integer is widened to a real in i + f.
  5. (E) confuses soundness with completeness. A sound checker may reject a program that would in fact never fail, so it need not reject exactly the unsafe ones — and it cannot: deciding whether an arbitrary program raises a type error is undecidable.

Final answer. Options (A), (B), (C) and (D).

Common misconception. Using “sound” and “complete” interchangeably. A sound checker errs on the safe side by rejecting too much; a complete one errs by accepting everything that is actually safe. Real static checkers are sound but deliberately incomplete.

  4. never accepts a program that can raise a run-time type error, but may reject some programs that cannot.
Show answer & solution

Detailed solution

Concept. Soundness is a one-sided guarantee: whatever the checker accepts is safe. Completeness is the other side: whatever is safe is accepted. A sound checker may be conservative and reject safe programs; it may not accept unsafe ones.

Step by step.

  1. (A) states completeness, not soundness.
