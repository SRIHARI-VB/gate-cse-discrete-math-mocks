DL-U1-Q01MCQeasy

The octal number (756)8 is equal to which one of the following binary strings?

  1. 111101110
  2. 111110110
  3. 111101100
  4. 111011110
Show answer & solution

Answer: Option (A)

Detailed solution

Concept. Base 8 and base 2 are linked by 8 = 23, so each octal digit is replaced by exactly three bits, independently of its neighbours.

Step by step.

  1. Split the octal number into its digits: 7, 5, 6.
  2. Convert each digit on its own: 7 = 111, 5 = 101, 6 = 110.
  3. Concatenate without dropping zeros: 111 101 110.
  4. Check through decimal: (756)8 = 7×64 + 5×8 + 6 = 448 + 40 + 6 = 494, and 1111011102 = 256 + 128 + 64 + 32 + 8 + 4 + 2 = 494.

Answer: 1111011102

Common misconception. Converting through decimal and then writing the binary of each digit separately, which silently introduces decimal-to-binary errors; or grouping in four bits, which is the rule for hexadecimal, not octal.

Takeaway. Fix the group width before you start: 3 bits per octal digit, 4 bits per hex digit, and never drop a leading zero inside a group.

DL-U1-Q02MCQeasy

What is the minimum number of bits needed to represent the decimal number 1000 as an unsigned binary integer?

  1. 9
  2. 10
  3. 11
  4. 12
Show answer & solution

Answer: Option (B)

Detailed solution

Concept. An unsigned binary number with n bits spans 0 to 2n − 1, so the requirement is 2n − 1 ≥ N, that is n ≥ ⌈log2(N + 1)⌉.

Step by step.

  1. Compute the powers around 1000: 29 = 512 and 210 = 1024.
  2. Nine bits reach only 511, which is below 1000.
  3. Ten bits reach 1023, and 1000 ≤ 1023, so ten bits suffice.

Answer: 10 bits

Common misconception. Answering 9 because 29 = 512 feels close to 1000, or using log10 instead of log2.

Takeaway. Count bits by the largest value the width can hold, not by the first power that looks large enough.

Which of the following represent the decimal value 255? (Select all that apply.)

  2. (377)8 in octal
  3. 11111111 in binary
  4. 0x1FF in hexadecimal
Show answer & solution

Answer: Options (A), (B), (C)

Detailed solution

Concept. The same quantity has one representation per base, so each option must be converted to decimal and compared with 255.

Step by step.

  1. 0xFF = 15×16 + 15 = 255. True.
  2. (377)8 = 3×64 + 7×8 + 7 = 192 + 56 + 7 = 255. True.

Takeaway. 0xFF is the largest 8-bit value; adding a hex digit pushes the number into the 9-bit range.

DL-U1-Q11MCQmedium

The binary fraction (0.1101)2 equals which decimal value?

  1. 0.8125
  2. 0.6875
  3. 0.875
  4. 0.625
Show answer & solution

Answer: Option (A)

Detailed solution

Concept. Bits to the right of the point carry the weights 2−1, 2−2, 2−3, and so on, so the digits are summed as fractions, not as integers.

Step by step.

  1. 1 × 2−1 = 0.5
  2. 1 × 2−2 = 0.25
  3. 0 × 2−3 = 0
  4. 1 × 2−4 = 0.0625
  5. Sum: 0.5 + 0.25 + 0 + 0.0625 = 0.8125.

Answer: 0.8125

Common misconception. Reading the four bits as the integer 13 and writing 0.13, or reversing the weight order and getting 0.6875.

Takeaway. Fractional bits halve as they move right; four bits can express only multiples of 1/16.

DL-U1-Q12MCQmedium

In which base b is the numeral (121)b equal to the decimal number 100?

  1. 9
  2. 8
  3. 10
  4. 11
Show answer & solution

Answer: Option (A)

Detailed solution

Concept. A positional numeral is evaluated by expanding its digits against powers of the base, which turns the question into an equation in b.

Step by step.

  1. Expand: (121)b = 1·b2 + 2·b + 1.
  2. Recognise the perfect square: b2 + 2b + 1 = (b + 1)2.
  3. Set (b + 1)2 = 100, so b + 1 = 10 and b = 9.
  4. Verify: (121)9 = 81 + 18 + 1 = 100.

Answer: b = 9

Common misconception. Trying bases by eye and stopping at 10 because 121 looks familiar in decimal; the digit 2 is legal in every base above 2, so legality alone does not identify the base.

Takeaway. Whenever the digits form a symmetric pattern, look for a perfect-square or perfect-cube structure before expanding.

  4. For any base b > 1, the numeral (1000)b equals b3.

Answer: Options (A), (B), (D)

Concept. Conversion between base 2 and base 2k is mechanical because each digit of the larger base is exactly k bits.

  2. -15
  3. -112
  4. +240

Concept. For an n-bit pattern whose leading bit is 1, the two's complement value is the unsigned value minus 2n.

DL-U1-Q13MCQmedium

In 8-bit two's complement arithmetic, the operation 0110 1001 − 1101 0110 produces which result, and does signed overflow occur?

  1. 1001 0011, and overflow occurs
  2. 1001 0011, and no overflow occurs
  3. 0100 1011, and overflow occurs
  4. 0011 0111, and no overflow occurs
Show answer & solution

Answer: Option (A)

Detailed solution

Concept. Subtraction is implemented as addition of the two's complement of the subtrahend, and signed overflow is decided by the signs of the operands and the result, not by the carry out.

Step by step.

  1. Interpret the operands: 0110 1001 = 105 and 1101 0110 = 214 − 256 = −42.
  2. The operation is 105 − (−42) = 105 + 42 = 147.
  3. The 8-bit signed range is −128 to +127, and 147 lies outside it, so signed overflow occurs.
  4. The bit pattern produced is 147 − 256 = −109, that is 1001 0011.
  5. Consistency check: both operands were positive after negation, and the result has its sign bit set, which is exactly the overflow signature.

Answer: 1001 0011, with overflow

Common misconception. Assuming that subtracting a negative number cannot overflow, or reading the carry out of the sign bit as an overflow flag; that carry detects unsigned wraparound only.

Takeaway. Overflow is a property of the operands' signs: two like-signed operands producing an unlike-signed result.

DL-U1-Q14MCQmedium

In 8-bit one's complement arithmetic, what is the value of (−5) + (−3) after the end-around carry is applied?

  1. -8
  2. -7
  3. +8
  4. -9
Show answer & solution

Answer: Option (A)

Detailed solution

Concept. One's complement addition adds the patterns and folds the carry out of the sign position back into the least significant bit; the result is a one's complement pattern, so a leading 1 means a negative number whose magnitude is the bitwise complement.

Step by step.

  1. −5 in 8-bit one's complement: 0000 0101 inverted = 1111 1010.
  2. −3: 0000 0011 inverted = 1111 1100.
  3. Add: 1111 1010 + 1111 1100 = 1 1111 0110, a 9-bit intermediate.
  4. Fold the carry back: 1111 0110 + 1 = 1111 0111.
  5. Read the pattern: leading bit 1, so negate by inverting: 0000 1000 = 8, giving −8.

Answer: −8

Common misconception. Dropping the end-around carry, which leaves 1111 0110 and gives −9; that is the classic one-bit error in one's complement.

Takeaway. One's complement needs the carry folded back; two's complement simply discards the carry. That difference is why two's complement is used in hardware.

DL-U1-Q17MSQmedium

Which of the following statements about n-bit two's complement numbers are TRUE? (Select all that apply.)

  1. The negation of a value is obtained by inverting all its bits and adding 1.
  2. The most negative value -2n-1 has no positive counterpart in the same width.
  3. -1 is represented as all ones.
  4. For every value x, the n-bit sum x + (-x) is 0 without overflow.
Show answer & solution

Answer: Options (A), (B), (C)

Detailed solution

Concept. Two's complement is a modular code: patterns are integers modulo 2n, with the upper half read as negative.

Step by step.

  1. Inverting and adding 1 computes the additive inverse modulo 2n, so statement A is true.
  2. The range is −2n−1 to 2n−1 − 1, which contains 2n−1 negatives but only 2n−1 − 1 positives, so −2n−1 is unmatched. Statement B is true.
  3. −1 is 2n − 1, whose n bits are all 1. Statement C is true.
  4. Take x = −2n−1. Its negation overflows, and the n-bit sum of the pattern with itself is 0 by wraparound but is not a valid result. Statement D is false.

Answer: Options (A), (B) and (C) only.

Common misconception. Believing every number has an opposite; the asymmetry of the range makes the most negative value its own negation.

Takeaway. The single exception at −2n−1 explains why negating the smallest value in a machine is a real and commonly hit bug.

Common misconception. Testing only the inputs where the two terms meet at a single cell. The hazard lives on the edge between two cells owned by different terms, so the K-map adjacency, not the algebraic overlap, is what must be checked.

Concept map used to build the questions

  • Latches and flip-flops. solving the cross-coupled NOR and NAND pairs for all four input combinations, the forbidden state and the race that follows its release, transparency of a gated latch against edge sampling by a master–slave pair, the race-around condition of a wide-pulse JK master–slave, and metastability as an unresolved analogue level rather than a wrong logic value.
  • Setup and hold times. the two halves of the sampling window around the active edge, the setup inequality tcq + tcomb + tsu ≤ T against the hold inequality tcq,min + tcomb,min ≥ th, why only the first contains the clock period, and what a negative hold time means.
  • Characteristic equations. next-state functions for D, T, JK and SR, reading a wiring back into the equation, and the row-pair test that distinguishes a toggle from a hold.
  • Shift registers. serial and parallel conversion, delay lines, left and right shifts as multiplication and division by 2 modulo the width, the ring counter of n states and the Johnson counter of 2n, and the unused states each leaves behind.
