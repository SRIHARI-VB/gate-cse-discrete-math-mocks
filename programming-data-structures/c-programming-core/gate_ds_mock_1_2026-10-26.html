DS-U1-Q01MCQeasy

Compiled with a C99-or-later compiler on a machine where int is 32 bits, what does this program print?

#include <stdio.h> int main(void) { printf("%d %d\n", 7 / 2 * 2, -7 / 2); return 0; }
  1. 6 -3
  2. 7 -3
  3. 6 -4
  4. 7 -4
Show answer & solution

Detailed solution

Concept. In C99 and later, integer division truncates towards zero, so -7 / 2 is -3, not -4. Multiplication and division have equal precedence and associate left to right.

Step by step.

  1. 7 / 2 is integer division: both operands are int, so the result is 3.
  2. Then 3 * 2 gives 6 — the multiply happens after the division because of left-to-right associativity.
  3. -7 / 2 discards the fractional part towards zero: the exact quotient is -3.5, truncated to -3.

Final answer. 6 -3

Common trap. Python and many pocket calculators use floor division, where -7 / 2 is -4. C truncates towards zero, so the second value is -3. The first trap is reading 7 / 2 * 2 as 7 / (2 * 2) = 1 or as floating point 7.

DS-U1-Q02MCQeasy

On an implementation where sizeof(int) is 4, what is the value of sizeof('A') in C?

  1. 1
  2. 2
  3. 4
  4. It depends on the character encoding used by the compiler
Show answer & solution

Detailed solution

Concept. In C a character constant such as 'A' has type int, not char. Its size is therefore the size of an int.

Step by step.

  1. The literal 'A' is a character constant whose type is int (C11 §6.4.4.4).
  2. No conversion to char takes place inside sizeof, because the operand of sizeof is not evaluated or converted to a narrower type.
  3. Hence sizeof('A') == sizeof(int) == 4.

Final answer. 4

Common trap. This is the classic C-versus-C++ confusion: in C++ 'A' has type char and the answer would be 1. The character encoding never changes the size of an int.

DS-U1-Q03MCQeasy

What does this program print?

#include <stdio.h> int main(void) { int a = 6, b = 3; printf("%d\n", a ^ b | a & b); return 0; }
  1. 7
  2. 5
  3. 2
  4. 1
Show answer & solution

Detailed solution

Concept. Bitwise AND binds tighter than XOR, which binds tighter than OR, so the expression groups as (a ^ b) | (a & b).

Step by step.

  1. a & b with a = 6 (110₂) and b = 3 (011₂) gives 010₂ = 2.
  2. a ^ b gives 101₂ = 5.
  3. 5 | 2 gives 101₂ | 010₂ = 111₂ = 7.

Final answer. 7

Common trap. Reading the expression left to right and computing (6 ^ 3) | 6 first, or assuming all three bitwise operators share precedence. The precedence order is & above ^ above |. Option 5 comes from evaluating only a ^ b and stopping.

DS-U1-Q04MCQmedium

What does this program print, assuming CHAR_BIT == 8?

#include <stdio.h> int main(void) { unsigned char c = 250; c = c + 10; printf("%u\n", c); return 0; }
  1. 260
  2. 4
  3. 0
  4. 10
Show answer & solution

Detailed solution

Concept. Unsigned arithmetic is performed modulo 2ⁿ for an n-bit type. Assignment to an unsigned type reduces the value modulo 2ⁿ; it never traps and never wraps into a negative number.

Step by step.

  1. In c + 10 the unsigned char is promoted to int, so the sum is the ordinary integer 260.
  2. The assignment back to unsigned char converts the value modulo 2⁸ = 256: 260 mod 256 = 4.
  3. So c holds 4 and %u prints 4.

Final answer. 4

Common trap. Answering 260 ignores the conversion on assignment; answering 0 assumes the value wraps to a signed negative and is then read as unsigned. Neither happens — the reduction is modulo 256 and the result is 4.

DS-U1-Q05MSQmedium

Which of the following statements about the standard C integer types are TRUE?

  1. sizeof(short) <= sizeof(int) on every conforming implementation
  2. sizeof(char) is 1 on every conforming implementation
  3. Signed integer overflow is defined to wrap around, exactly as it does for unsigned types
  4. Plain char is signed on every conforming implementation
Show answer & solution

Detailed solution

Concept. The C standard fixes minimum ranges and a rank order for the integer types, but leaves the size of most of them to the implementation. It also leaves signed overflow undefined and the signedness of plain char implementation-defined.

Step by step.

  1. (A) is true: the standard requires sizeof(short) <= sizeof(int) <= sizeof(long), so a short can never be larger than an int.
  2. (B) is true: sizeof(char) == 1 by definition — a byte in C is exactly one char, whatever its bit width.
  3. (C) is false: unsigned arithmetic is defined modulo 2ⁿ, but signed overflow is undefined behaviour. An optimiser may assume it never happens.
  4. (D) is false: whether plain char behaves as signed char or unsigned char is implementation-defined; only signed char and unsigned char are distinct types with fixed signedness.

Final answer. Options (A) and (B)

Common trap. The tempting error is (C): students see unsigned wrap-around and assume signed types do the same. They do not — signed overflow is undefined, and a program that relies on it can behave differently at -O0 and -O2. Option (D) is the other classic: char is not guaranteed signed.

DS-U1-Q06MCQmedium

What does this program print?

#include <stdio.h> int main(void) { int x, y = 2; x = (y += 3, y * 2); printf("%d\n", x); return 0; }
  1. 5
  2. 10
  3. 8
  4. 2
Show answer & solution

Detailed solution

Concept. The comma operator evaluates its left operand, discards that value, then evaluates the right operand and yields its value. The parentheses make the whole comma expression the right-hand side of the assignment to x.

Step by step.

  1. The left operand y += 3 runs first: y becomes 2 + 3 = 5; its value 5 is discarded.
  2. The right operand y * 2 is then evaluated with the updated y: 5 * 2 = 10.
  3. The comma expression yields 10, which is assigned to x.

Final answer. 10

Common trap. Two traps. First, forgetting that the left operand has already changed y, so the second operand uses 5 rather than 2 — that gives the distractor 4 or 5. Second, reading the comma as a declaration separator; inside an expression it is the comma operator. Note also that int x, y = 2; initialises only y.

DS-U1-Q07NAThard

What does this program print?

#include <stdio.h> int main(void) { unsigned char c = 0xF0; int r = c << 4; printf("%d\n", r); return 0; }
    Show answer & solution

    Detailed solution

    Concept. In a shift expression the operands are promoted to int first (the usual arithmetic conversions), so the left shift happens on a 32-bit value, not on an 8-bit one. The result of c << 4 is therefore not reduced modulo 256.

    Step by step.

    1. c holds 0xF0 = 240.
    2. Integer promotion converts c to the int value 240 before the shift.
    3. 240 << 4 = 240 × 16 = 3840, which is 0xF00 and still fits in a 32-bit int.
    4. The assignment to r is a plain int assignment, so no truncation occurs and %d prints 3840.

    Final answer. 3840

    Common trap. The classic error is to keep the value 8 bits wide and answer 0: 0xF0 << 4 truncated to 8 bits is 0x00. That would be true only if the shift were performed in unsigned char arithmetic, which C does not do. Remember that shifts do not truncate to the left operand's type.

    DS-U1-Q08MCQeasy

    What does this program print? (It compiles; the compiler only warns.)

    #include <stdio.h> int main(void) { int x = 0; if (x = 0) printf("A\n"); else printf("B\n"); return 0; }
    1. A
    2. B
    3. Nothing is printed
    4. It does not compile
    Show answer & solution

    Detailed solution

    Concept. The condition of an if is any scalar expression; here it is an assignment expression, whose value is the value stored. Storing 0 makes the condition false.

    Step by step.

    1. x = 0 assigns 0 to x and yields the value 0.
    2. A zero value is false, so the else branch runs.
    3. The program prints B.

    Final answer. B

    Common trap. Reading x = 0 as the comparison x == 0. That comparison would be true and print A. This is why good compilers warn about an assignment used as a condition. With x = 1 the program would print A.

    DS-U1-Q09MCQmedium

    What does this program print?

    #include <stdio.h> int main(void) { int i, j; for (i = 0, j = 10; i < j; i++, j--) ; printf("%d %d\n", i, j); return 0; }
    1. 4 6
    2. 5 5
    3. 6 4
    4. 10 0
    Show answer & solution

    Detailed solution

    Concept. A for header has three parts separated by semicolons: initialisation, condition and update. The update here is a single comma expression, so both i++ and j-- run at the end of every iteration.

    Step by step.

    1. Start: i = 0, j = 10; condition 0 < 10 true.
    2. After each iteration both counters move: (1, 9), (2, 8), (3, 7), (4, 6).
    3. At (5, 5) the condition 5 < 5 is false, so the loop stops with i = 5 and j = 5.

    Final answer. 5 5

    Common trap. Stopping at 4 6 — that is the state at the start of the last successful iteration, not the state after the failing test. The update clause always runs before the condition is re-tested, so the counters meet at 5.

    DS-U1-Q10NATeasy

    What does this program print?

    #include <stdio.h> int main(void) { int c = 0; for (int i = 0; i < 5; i++) for (int j = i; j < 5; j++) c++; printf("%d\n", c); return 0; }
      Show answer & solution

      Detailed solution

      Concept. The inner loop starts at j = i, so it runs 5 - i times for each value of i. The total is the sum of an arithmetic series.

      Step by step.

      1. For i = 0, 1, 2, 3, 4 the inner loop runs 5, 4, 3, 2, 1 times.
      2. Total: 5 + 4 + 3 + 2 + 1 = 15.
      3. Equivalently n(n + 1)/2 with n = 5, i.e. the number of pairs (i, j) with 0 ≤ i ≤ j < 5.

      Final answer. 15

      Common trap. Assuming both loops always run 5 times and answering 25, or counting only the strictly upper-triangular pairs (10) by starting the inner loop at j = i + 1. The condition is j < 5 with j starting at i, so the diagonal is included.

      DS-U1-Q11MCQmedium

      What does this program print?

      #include <stdio.h> int main(void) { int x = 2; switch (x) { case 1: printf("one"); case 2: printf("two"); case 3: printf("three"); break; default: printf("other"); } return 0; }
      1. two
      2. twothree
      3. onetwothree
      4. twoother
      Show answer & solution

      Detailed solution

      Concept. A switch transfers control to the matching case label and then simply falls through the following statements until a break or the end of the block. Labels do not act as implicit exits.

      Step by step.

      1. The controlling value is 2, so control jumps to case 2:.
      2. The statement printf("two") runs.
      3. There is no break after it, so execution continues into case 3: and prints three.
      4. The break after case 3: ends the switch, so the default is never reached.

      Final answer. twothree

      Common trap. Assuming each case is exclusive, as in an if-else chain, and answering two. Fall-through is the default in C; a break is required at the end of every case you want to end. Note also that the default is skipped here only because a break intervened.

      DS-U1-Q12MSQmedium

      On a typical 32-bit implementation, which of these loops TERMINATE?

      1. for (unsigned int i = 10; i >= 0; i--) { }
      2. int i = 0; while (i < 5) i += 2;
      3. int i = 0; do { i++; } while (i < 0);
      4. for (int i = 0; i != 10; i += 3) { }
      Show answer & solution

      Detailed solution

      Concept. A loop terminates when its condition eventually becomes false. For unsigned counters and for equality tests with a stride that does not divide the gap, the condition can be permanently true.

      Step by step.

      1. (A) An unsigned int is never negative, so i >= 0 is always true. When i is 0 the decrement wraps to 4294967295 and the loop never ends.
      2. (B) i takes 0, 2, 4 and then 6, at which point 6 < 5 is false. It terminates.
      3. (C) The body runs once (i becomes 1) and then 1 < 0 is false. A do-while always executes its body at least once. It terminates.
      4. (D) i takes 0, 3, 6, 9, 12, … and never equals 10, so the test is never false. It does not terminate.

      Final answer. Options (B) and (C)

      Common trap. Option (A) is the trap: the loop looks exactly like a signed countdown that ends at 0, but on an unsigned type the final decrement wraps instead of going negative. Option (D) shows the second trap — != is safe only when the stride divides the target.

      DS-U1-Q13MCQhard

      What does this program print?

      #include <stdio.h> int main(void) { int s = 0; for (int i = 0; i < 5; i++) { switch (i) { case 0: continue; case 1: s += 1; case 2: s += 2; break; case 3: s += 4; default: s += 8; } s += 100; } printf("%d\n", s); return 0; }
      1. 425
      2. 325
      3. 417
      4. 405
      Show answer & solution

      Detailed solution

      Concept. Inside a switch that is inside a loop, continue belongs to the loop: it abandons the rest of the switch and the rest of the loop body, and jumps to the loop's update step. Fall-through still applies between case labels.

      Step by step.

      1. i = 0: case 0 executes continue, so neither the switch nor the trailing s += 100 runs. s = 0.
      2. i = 1: case 1 adds 1, falls into case 2 and adds 2, then break exits the switch. s += 100 runs: s = 3 + 100 = 103.
      3. i = 2: case 2 adds 2 and breaks, then s += 100: s = 105 + 100 = 205.
      4. i = 3: case 3 adds 4 and falls through into default, adding 8: s = 209 + 8 = 217; then s += 100 gives 317.
      5. i = 4: default adds 8: s = 325; then s += 100 gives 425.

      Final answer. 425

      Common trap. Two mistakes produce the distractors. Treating continue as break — that is, letting the loop carry on to s += 100 for i = 0 — gives 325. Forgetting the fall-through from case 1 into case 2, or from case 3 into default, gives 417 or 405. Note that in C, unlike Java, continue inside a switch acts on the enclosing loop.

      DS-U1-Q14MCQeasy

      What does this program print?

      #include <stdio.h> void swap(int a, int b) { int t = a; a = b; b = t; } int main(void) { int x = 1, y = 2; swap(x, y); printf("%d %d\n", x, y); return 0; }
      1. 1 2
      2. 2 1
      3. 2 2
      4. 1 1
      Show answer & solution

      Detailed solution

      Concept. C has only call by value. The parameters a and b are fresh objects inside swap, initialised with copies of the arguments, so swapping them changes nothing in the caller.

      Step by step.

      1. The call copies x into a and y into b.
      2. The body exchanges the copies: a = 2, b = 1.
      3. On return those copies are destroyed; x and y are untouched.
      4. The program prints 1 2.

      Final answer. 1 2

      Common trap. Expecting the swap to work, as it would in a language with call by reference. To make it work in C you must pass addresses — void swap(int *a, int *b) called as swap(&x, &y) — and dereference inside.

      DS-U1-Q15NATeasy

      What does this program print?

      #include <stdio.h> int sq(int x) { return x * x; } int main(void) { int s = 0; for (int i = 1; i <= 4; i++) s += sq(i); printf("%d\n", s); return 0; }
        Show answer & solution

        Detailed solution

        Concept. The function is called once per iteration with the current value of i, and its return value is added to the accumulator.

        Step by step.

        1. Calls: sq(1) = 1, sq(2) = 4, sq(3) = 9, sq(4) = 16.
        2. Sum: 1 + 4 + 9 + 16 = 30.
        3. Closed form: n(n + 1)(2n + 1)/6 = 4·5·9/6 = 30 for n = 4.

        Final answer. 30

        Common trap. Summing 1 + 2 + 3 + 4 = 10 by reading the call as sq(i) = i, or stopping the loop at i < 4 and losing the 16. The upper bound is i <= 4, so four calls are made.

        DS-U1-Q16MCQmedium

        What does this program print?

        #include <stdio.h> int f(void) { static int c = 0; c++; return c; } int main(void) { f(); f(); printf("%d\n", f()); return 0; }
        1. 1
        2. 2
        3. 3
        4. 0
        Show answer & solution

        Detailed solution

        Concept. A static local variable is created once, before the program starts, and lives for the whole execution. It keeps its value between calls; only its name is scoped to the function.

        Step by step.

        1. The initialiser c = 0 is applied once, at program start — not on every call.
        2. First call: c becomes 1, returns 1. Second call: becomes 2, returns 2.
        3. The third call (the one inside printf) makes c = 3 and returns 3, which is printed.

        Final answer. 3

        Common trap. Assuming the local is re-initialised on every call and answering 1. That would be true for an automatic local such as int c = 0;. static changes storage duration, not scope: c is still invisible outside f.

        DS-U1-Q17MSQmedium

        An array declared as int a[10] is passed to a function declared as void g(int a[]) and called as g(a). Which statements are TRUE?

        1. Inside g the parameter is a pointer, so sizeof a gives the size of a pointer, not 40
        2. The call copies all ten elements into the activation record of g
        3. An assignment to a[i] inside g is visible to the caller
        4. The number of elements cannot be recovered from the parameter alone
        Show answer & solution

        Detailed solution

        Concept. In a parameter list, an array declarator is adjusted to a pointer type: int a[] and int a[10] both mean int *a. What is passed is the address of the first element, not a copy of the array.

        Step by step.

        1. (A) is true: after adjustment the parameter has type int *, so sizeof a is the pointer size (4 or 8 bytes), never 40.
        2. (B) is false: C never copies an array on a call. Only the pointer value is copied.
        3. (C) is true: a[i] designates the caller's element through the pointer, so writes are visible after return.
        4. (D) is true: the pointer carries no length, which is why such functions take a separate count parameter.

        Final answer. Options (A), (C) and (D)

        Common trap. The natural but wrong reading is (B) — "arrays are passed by value like everything else". The value that is copied is the address, so element changes propagate while reassigning the pointer itself does not. And because the length is lost, sizeof inside the callee is the classic way to get a wrong byte count.

        DS-U1-Q18MCQmedium

        What does this program print?

        #include <stdio.h> void inc(int *p) { *p = *p + 1; } void bump(int p) { p = p + 1; } int main(void) { int a = 5; inc(&a); bump(a); printf("%d\n", a); return 0; }
        1. 5
        2. 6
        3. 7
        4. 8
        Show answer & solution

        Detailed solution

        Concept. Only the callee that receives an address can change the caller's object. inc dereferences its pointer and writes through it; bump increments its own local copy.

        Step by step.

        1. inc(&a) passes the address of a; *p = *p + 1 stores 6 in a itself.
        2. bump(a) passes the value 6 into a new local p; p = p + 1 makes that local 7 and it is discarded on return.
        3. So a is 6 and the program prints 6.

        Final answer. 6

        Common trap. Adding both increments and answering 7, on the assumption that bump also changes the caller. A value parameter is a copy; only writes through a pointer reach the caller. A related trap is writing void inc(int p) and expecting the caller to change.

        DS-U1-Q19NAThard

        What does this program print?

        #include <stdio.h> int f(int n) { static int s = 0; s = s + n; return s; } int main(void) { int i, t = 0; for (i = 1; i <= 4; i++) t += f(i); printf("%d\n", t); return 0; }
          Show answer & solution

          Detailed solution

          Concept. A static local keeps its value across calls, so f returns a running total rather than just n. The calls here are sequential, so the order of evaluation is fully determined.

          Step by step.

          1. Call f(1): s = 0 + 1 = 1, returns 1. t = 1.
          2. Call f(2): s = 1 + 2 = 3, returns 3. t = 4.
          3. Call f(3): s = 3 + 3 = 6, returns 6. t = 10.
          4. Call f(4): s = 6 + 4 = 10, returns 10. t = 20.

          Final answer. 20

          Common trap. Two errors. Ignoring static and computing 1 + 2 + 3 + 4 = 10 gives the distractor 10. Summing the returned values but forgetting that s also accumulates them (answering 10 + 10 = 20 by a wrong route) is harmless here, but the reliable method is to track s call by call. Note the initialiser runs only once for the whole program.

          Recursion & stack execution 6
          DS-U1-Q20MCQeasy

          What does this program print?

          #include <stdio.h> int f(int n) { if (n == 0) return 0; return n + f(n - 1); } int main(void) { printf("%d\n", f(4)); return 0; }
          1. 4
          2. 10
          3. 24
          4. 6
          Show answer & solution

          Detailed solution

          Concept. The recursive call is inside an addition, so each frame must wait for the value returned by the frame below it before it can finish. The results are added on the way back up the stack.

          Step by step.

          1. Calls descend: f(4) → f(3) → f(2) → f(1) → f(0).
          2. The base case returns 0. Unwinding: f(1) = 1 + 0 = 1, f(2) = 2 + 1 = 3, f(3) = 3 + 3 = 6, f(4) = 4 + 6 = 10.
          3. This is the sum 1 + 2 + 3 + 4 = 10.

          Final answer. 10

          Common trap. Answering 24 treats the function as a factorial (4! = 24); the multiplication is nowhere in the code. Answering 4 reads the return as just n. The addition of the returned value is what makes this a sum.

          DS-U1-Q21MSQmedium

          The program below prints a sequence of digits. Which statements about that output are TRUE?

          #include <stdio.h> void f(int n) { if (n > 0) { printf("%d", n % 2); f(n / 2); } } int main(void) { f(13); return 0; }
          1. The digits are printed in the order 1, 0, 1, 1
          2. The first digit printed is the least significant bit of 13
          3. The program prints the binary numeral of 13 in the usual most-significant-first order
          4. The last digit printed is the most significant bit of 13
          Show answer & solution

          Detailed solution

          Concept. Each frame prints the least significant remaining bit and only then recurses on the quotient, so the bits emerge least significant first. Code placed before a recursive call runs on the way down the stack.

          Step by step.

          1. f(13): 13 mod 2 = 1, print 1, recurse on 13 / 2 = 6.
          2. f(6): 6 mod 2 = 0, print 0, recurse on 3. f(3): print 1, recurse on 1. f(1): print 1, recurse on 0, which stops.
          3. Digits printed: 1, 0, 1, 1. The first is the low-order bit of 13; the last, printed by the deepest frame that prints anything, is the high-order bit. 13 is 1101₂, so the output is that numeral reversed.

          Final answer. Options (A), (B) and (D)

          Common trap. Option (C) is the trap: students assume a bit-printing recursion prints the numeral in reading order. Moving the printf after the recursive call would do exactly that and produce 1101. Option (D) is easy to get wrong by assuming the last frame is f(13) — it is the deepest one.

          DS-U1-Q22MCQeasy

          What does this program print?

          #include <stdio.h> void f(int n) { if (n == 0) return; f(n - 1); printf("%d", n); } int main(void) { f(3); return 0; }
          1. 321
          2. 123
          3. 0123
          4. 3
          Show answer & solution

          Detailed solution

          Concept. The printf is placed after the recursive call, so it runs while the stack unwinds — from the deepest frame back to the shallowest.

          Step by step.

          1. Calls descend f(3) → f(2) → f(1) → f(0); f(0) returns immediately.
          2. Unwinding, f(1) prints 1, then f(2) prints 2, then f(3) prints 3.
          3. The output is 123.

          Final answer. 123

          Common trap. Answering 321 assumes the print happens before the recursion. The distinction is worth memorising: code before the recursive call runs on the way down (most significant first), code after it runs on the way up (least significant first). Nothing prints 0 because the base case returns before printing.

          DS-U1-Q23MSQhard

          Which statements about recursion and the run-time stack in C are TRUE?

          1. Any recursive function can be rewritten iteratively with an explicit stack that mimics the activation records
          2. A tail-recursive call can reuse the caller's activation record when the compiler performs tail-call optimisation
          3. The C standard guarantees that recursion depth is limited only by available memory
          4. Each active call has its own copy of the parameters and of the automatic local variables
          Show answer & solution

          Detailed solution

          Concept. A call in C uses an activation record (frame) on the run-time stack, holding the return address, the saved state, the parameters and the automatic locals. Recursion is therefore just a sequence of frames, and it can always be simulated explicitly.

          Step by step.

          1. (A) is true: a recursive call does nothing that a manually maintained stack of the same frames cannot reproduce.
          2. (B) is true: when the call is the last operation of the caller, the callee can reuse the frame; this is a permitted optimisation, and -foptimize-sibling-calls enables it in GCC.
          3. (C) is false: the standard sets no minimum depth and no guarantee. The stack is finite and typically a few megabytes, so deep recursion overflows it — a crash, not an out-of-memory error.
          4. (D) is true: that per-call copy is exactly why a value parameter cannot be changed in the caller and why automatic locals do not interfere across frames.

          Final answer. Options (A), (B) and (D)

          Common trap. Option (C) is the trap: students confuse "the stack grows as needed" with a standard guarantee. In practice the depth limit is small (tens of thousands of frames at most) and exceeding it is undefined behaviour. A second trap is assuming (B) happens automatically in C — it is an optimisation, not a language requirement.

          DS-U1-Q24NATeasy

          What does this program print?

          #include <stdio.h> int f(int n) { return (n < 2) ? n : f(n - 1) + f(n - 2); } int main(void) { printf("%d\n", f(6)); return 0; }
            Show answer & solution

            Detailed solution

            Concept. This is the Fibonacci recurrence with base values f(0) = 0 and f(1) = 1. Each value is the sum of the two before it.

            Step by step.

            1. Compute upwards: f(2) = 1 + 0 = 1, f(3) = 1 + 1 = 2, f(4) = 2 + 1 = 3, f(5) = 3 + 2 = 5, f(6) = 5 + 3 = 8.
            2. The sequence is 0, 1, 1, 2, 3, 5, 8 for n = 0…6.
            3. So the program prints 8.

            Final answer. 8

            Common trap. Shifting the index by one and answering 5 (the value of f(5)) or 13 (the value of f(7)). Note also that this naive recursion recomputes the same subproblems repeatedly — f(6) needs 25 calls — which is why the exponential cost of the naive version matters.

            DS-U1-Q25MCQhard

            What does this program print?

            #include <stdio.h> int f(int n, int *c) { (*c)++; if (n <= 1) return 1; return f(n - 1, c) + f(n - 2, c); } int main(void) { int c = 0; f(5, &c); printf("%d\n", c); return 0; }
            1. 9
            2. 15
            3. 25
            4. 8
            Show answer & solution

            Detailed solution

            Concept. The counter is incremented once per call, in every frame, through a pointer shared by all of them. The answer is the total number of calls made by the recursion tree, not the value returned.

            Step by step.

            1. Let C(n) be the number of calls made by f(n). One call happens at the top, plus the calls made by its two children.
            2. Base cases: C(0) = C(1) = 1. For n ≥ 2: C(n) = 1 + C(n − 1) + C(n − 2).
            3. Compute: C(2) = 1 + 1 + 1 = 3, C(3) = 1 + 3 + 1 = 5, C(4) = 1 + 5 + 3 = 9, C(5) = 1 + 9 + 5 = 15.
            4. So c ends at 15.

            Final answer. 15

            Common trap. Answering 8, the value f returns, instead of the count. Answering 9 is C(4), the count one level down. The recurrence C(n) = C(n−1) + C(n−2) + 1 is worth remembering: for n = 5 it gives 15, and in general it grows like the Fibonacci numbers — the reason naive recursion here is exponential.
