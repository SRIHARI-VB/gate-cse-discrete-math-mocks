DS-U1-Q01MCQeasy

Compiled with a C99-or-later compiler on a machine where int is 32 bits, what does this program print?

#include <stdio.h> int main(void) { printf("%d %d\n", 7 / 2 * 2, -7 / 2); return 0; }
  1. 6 -3
  2. 7 -3
  3. 6 -4
  4. 7 -4
Show answer & solution

Answer: Option (A)

Detailed solution

Concept. In C99 and later, integer division truncates towards zero, so -7 / 2 is -3, not -4. Multiplication and division have equal precedence and associate left to right.

Step by step.

  1. 7 / 2 is integer division: both operands are int, so the result is 3.
  2. Then 3 * 2 gives 6 — the multiply happens after the division because of left-to-right associativity.
  3. -7 / 2 discards the fractional part towards zero: the exact quotient is -3.5, truncated to -3.

Final answer. 6 -3

Common trap. Python and many pocket calculators use floor division, where -7 / 2 is -4. C truncates towards zero, so the second value is -3. The first trap is reading 7 / 2 * 2 as 7 / (2 * 2) = 1 or as floating point 7.

DS-U1-Q02MCQeasy

On an implementation where sizeof(int) is 4, what is the value of sizeof('A') in C?

  1. 1
  2. 2
  3. 4
  4. It depends on the character encoding used by the compiler
Show answer & solution

Answer: Option (C)

Detailed solution

Concept. In C a character constant such as 'A' has type int, not char. Its size is therefore the size of an int.

Step by step.

  1. The literal 'A' is a character constant whose type is int (C11 §6.4.4.4).
  2. No conversion to char takes place inside sizeof, because the operand of sizeof is not evaluated or converted to a narrower type.
  3. Hence sizeof('A') == sizeof(int) == 4.

Final answer. 4

Common trap. This is the classic C-versus-C++ confusion: in C++ 'A' has type char and the answer would be 1. The character encoding never changes the size of an int.

DS-U1-Q03MCQeasy

What does this program print?

#include <stdio.h> int main(void) { int a = 6, b = 3; printf("%d\n", a ^ b | a & b); return 0; }
  1. 7
  2. 5
  3. 2
  4. 1
Show answer & solution

Answer: Option (A)

Detailed solution

Concept. Bitwise AND binds tighter than XOR, which binds tighter than OR, so the expression groups as (a ^ b) | (a & b).

Step by step.

  1. a & b with a = 6 (110₂) and b = 3 (011₂) gives 010₂ = 2.
  2. a ^ b gives 101₂ = 5.
  3. 5 | 2 gives 101₂ | 010₂ = 111₂ = 7.

Final answer. 7

Common trap. Reading the expression left to right and computing (6 ^ 3) | 6 first, or assuming all three bitwise operators share precedence. The precedence order is & above ^ above |. Option 5 comes from evaluating only a ^ b and stopping.

DS-U1-Q04MCQmedium

What does this program print, assuming CHAR_BIT == 8?

#include <stdio.h> int main(void) { unsigned char c = 250; c = c + 10; printf("%u\n", c); return 0; }
  1. 260
  2. 4
  3. 0
  4. 10
Show answer & solution

Answer: Option (B)

Detailed solution

Concept. Unsigned arithmetic is performed modulo 2ⁿ for an n-bit type. Assignment to an unsigned type reduces the value modulo 2ⁿ; it never traps and never wraps into a negative number.

Step by step.

  1. In c + 10 the unsigned char is promoted to int, so the sum is the ordinary integer 260.
  2. The assignment back to unsigned char converts the value modulo 2⁸ = 256: 260 mod 256 = 4.
  3. So c holds 4 and %u prints 4.

Final answer. 4

Common trap. Answering 260 ignores the conversion on assignment; answering 0 assumes the value wraps to a signed negative and is then read as unsigned. Neither happens — the reduction is modulo 256 and the result is 4.

DS-U1-Q05MSQmedium

Which of the following statements about the standard C integer types are TRUE?

  1. sizeof(short) <= sizeof(int) on every conforming implementation
  2. sizeof(char) is 1 on every conforming implementation
  3. Signed integer overflow is defined to wrap around, exactly as it does for unsigned types
  4. Plain char is signed on every conforming implementation
Show answer & solution

Answer: Options (A) and (B)

Detailed solution

Concept. The C standard fixes minimum ranges and a rank order for the integer types, but leaves the size of most of them to the implementation. It also leaves signed overflow undefined and the signedness of plain char implementation-defined.

Step by step.

  1. (A) is true: the standard requires sizeof(short) <= sizeof(int) <= sizeof(long), so a short can never be larger than an int.
  2. (B) is true: sizeof(char) == 1 by definition — a byte in C is exactly one char, whatever its bit width.
  3. (C) is false: unsigned arithmetic is defined modulo 2ⁿ, but signed overflow is undefined behaviour. An optimiser may assume it never happens.
  4. (D) is false: whether plain char behaves as signed char or unsigned char is implementation-defined; only signed char and unsigned char are distinct types with fixed signedness.

Final answer. Options (A) and (B)

Common trap. The tempting error is (C): students see unsigned wrap-around and assume signed types do the same. They do not — signed overflow is undefined, and a program that relies on it can behave differently at -O0 and -O2. Option (D) is the other classic: char is not guaranteed signed.

DS-U1-Q06MCQmedium

What does this program print?

#include <stdio.h> int main(void) { int x, y = 2; x = (y += 3, y * 2); printf("%d\n", x); return 0; }
  1. 5
  2. 10
  3. 8
  4. 2
Show answer & solution

Answer: Option (B)

Detailed solution

Concept. The comma operator evaluates its left operand, discards that value, then evaluates the right operand and yields its value. The parentheses make the whole comma expression the right-hand side of the assignment to x.

Step by step.

  1. The left operand y += 3 runs first: y becomes 2 + 3 = 5; its value 5 is discarded.
  2. The right operand y * 2 is then evaluated with the updated y: 5 * 2 = 10.
  3. The comma expression yields 10, which is assigned to x.

Final answer. 10

Common trap. Two traps. First, forgetting that the left operand has already changed y, so the second operand uses 5 rather than 2 — that gives the distractor 4 or 5. Second, reading the comma as a declaration separator; inside an expression it is the comma operator. Note also that int x, y = 2; initialises only y.

DS-U1-Q07NAThard

What does this program print?

#include <stdio.h> int main(void) { unsigned char c = 0xF0; int r = c << 4; printf("%d\n", r); return 0; }
Show answer & solution

Answer: 3840

Detailed solution

Concept. In a shift expression the operands are promoted to int first (the usual arithmetic conversions), so the left shift happens on a 32-bit value, not on an 8-bit one. The result of c << 4 is therefore not reduced modulo 256.

Step by step.

  1. c holds 0xF0 = 240.
  2. Integer promotion converts c to the int value 240 before the shift.
  3. 240 << 4 = 240 × 16 = 3840, which is 0xF00 and still fits in a 32-bit int.
  4. The assignment to r is a plain int assignment, so no truncation occurs and %d prints 3840.

Final answer. 3840

Common trap. The classic error is to keep the value 8 bits wide and answer 0: 0xF0 << 4 truncated to 8 bits is 0x00. That would be true only if the shift were performed in unsigned char arithmetic, which C does not do. Remember that shifts do not truncate to the left operand's type.

DS-U1-Q26MCQeasy

On an implementation where int is 4 bytes and float is 4 bytes, what is the value of sizeof(1.0f + 1)?

  1. 1
  2. 4
  3. 8
  4. It cannot be determined without knowing the value of 1.0f + 1.
Show answer & solution

Answer: Option (B)

Detailed solution

Concept. The type of an arithmetic expression is fixed by the usual arithmetic conversions, and sizeof reports the size of that type, not of a computed value.

Step by step.

  1. 1.0f has type float and 1 has type int.
  2. The usual arithmetic conversions convert the int operand to float, so the sum has type float.
  3. There is no double in the expression: a float stays float unless a double operand forces promotion.
  4. sizeof(float) is 4 on this implementation, so the value is 4.

What does this program print?

#include <stdio.h> int main(void) { int a = 017, b = 0x1F; printf("%d %d\n", a, b); return 0; }
  1. 15 31
  2. 17 31
  3. 15 1F
  4. 017 31

Answer: Option (A)

Detailed solution

Concept. The base of an integer literal is set by its prefix: a leading 0 means octal, 0x means hexadecimal, and no prefix means decimal.

Step by step.

  1. 017 is octal: 1·8 + 7 = 15.
  2. 0x1F is hexadecimal: 1·16 + 15 = 31.

DS-U1-Q28MCQmedium

On a machine where int is 32 bits, what does this program print?

#include <stdio.h> int main(void) { int i = -1; unsigned int u = 1; printf("%d\n", i < u); return 0; }
  1. 1
  2. 0
  3. -1
  4. The behaviour is undefined
Show answer & solution

Answer: Option (B)

Detailed solution

Concept. When an int meets an unsigned int of the same rank, the usual arithmetic conversions turn the int into unsigned int before the comparison.

Step by step.

  1. The conversion of a negative value to unsigned is defined as arithmetic modulo 2³², so -1 becomes 4294967295u.
  2. The comparison is therefore 4294967295u < 1u, which is false.
  3. A relational operator yields int 0 or 1, so the value passed to %d is 0.
  4. Hence the program prints 0.

Answer: Option (B)

Common misconception. Reasoning in signed arithmetic, where −1 < 1 is true, and answering 1. This is the mirror image of the classic -1 < sizeof(x) trap: an unsigned operand in a mixed expression silently reinterprets the signed value.

DS-U1-Q29MCQmedium

What does this program print?

#include <stdio.h> int main(void) { int x = 1; x <<= 3; x |= 1; x ^= 5; printf("%d\n", x); return 0; }
  1. 8
  2. 9
  3. 12
  4. 13
Show answer & solution

Answer: Option (C)

Detailed solution

Concept. Compound assignment operators apply one bitwise operation at a time, in the order written, and each one assigns the result back to the variable.

Step by step.

  1. x = 1, i.e. binary 0001.
  2. x <<= 3 shifts left by three: 1000, so x = 8.
  3. x |= 1 sets the low bit: 1001, so x = 9.
  4. x ^= 5 is 1001 XOR 0101 = 1100, so x = 12.

Answer: Option (C)

Common misconception. Using | and ^ in the wrong order, or replacing the XOR by an OR, which gives 13. Bit 3 survives the OR and is cleared by the XOR because 5 has that bit set.

Concept. The condition of an if is any scalar expression; here it is an assignment expression, whose value is the value stored. Storing 0 makes the condition false.

DS-U1-Q09MCQmedium

What does this program print?

#include <stdio.h> int main(void) { int i, j; for (i = 0, j = 10; i < j; i++, j--) ; printf("%d %d\n", i, j); return 0; }
  1. 4 6
  2. 5 5
  3. 6 4
  4. 10 0
Show answer & solution

Answer: Option (B)

Detailed solution

Concept. A for header has three parts separated by semicolons: initialisation, condition and update. The update here is a single comma expression, so both i++ and j-- run at the end of every iteration.

Step by step.

  1. Start: i = 0, j = 10; condition 0 < 10 true.
  2. After each iteration both counters move: (1, 9), (2, 8), (3, 7), (4, 6).
  3. At (5, 5) the condition 5 < 5 is false, so the loop stops with i = 5 and j = 5.

Final answer. 5 5

Common trap. Stopping at 4 6 — that is the state at the start of the last successful iteration, not the state after the failing test. The update clause always runs before the condition is re-tested, so the counters meet at 5.

DS-U1-Q10NATeasy

What does this program print?

#include <stdio.h> int main(void) { int c = 0; for (int i = 0; i < 5; i++) for (int j = i; j < 5; j++) c++; printf("%d\n", c); return 0; }
Show answer & solution

Answer: 15

Detailed solution

Concept. The inner loop starts at j = i, so it runs 5 - i times for each value of i. The total is the sum of an arithmetic series.

Step by step.

  1. For i = 0, 1, 2, 3, 4 the inner loop runs 5, 4, 3, 2, 1 times.

Common trap. Assuming both loops always run 5 times and answering 25, or counting only the strictly upper-triangular pairs (10) by starting the inner loop at j = i + 1. The condition is j < 5 with j starting at i, so the diagonal is included.

DS-U1-Q11MCQmedium

What does this program print?

#include <stdio.h> int main(void) { int x = 2; switch (x) { case 1: printf("one"); case 2: printf("two"); case 3: printf("three"); break; default: printf("other"); } return 0; }
  1. two
  2. twothree
  3. onetwothree
  4. twoother
Show answer & solution

Answer: Option (B)

Detailed solution

Concept. A switch transfers control to the matching case label and then simply falls through the following statements until a break or the end of the block. Labels do not act as implicit exits.

Step by step.

  1. The controlling value is 2, so control jumps to case 2:.
  2. The statement printf("two") runs.
  3. There is no break after it, so execution continues into case 3: and prints three.
  4. The break after case 3: ends the switch, so the default is never reached.

Common trap. Assuming each case is exclusive, as in an if-else chain, and answering two. Fall-through is the default in C; a break is required at the end of every case you want to end. Note also that the default is skipped here only because a break intervened.

DS-U1-Q12MSQmedium

On a typical 32-bit implementation, which of these loops TERMINATE?

  1. for (unsigned int i = 10; i >= 0; i--) { }
  2. int i = 0; while (i < 5) i += 2;
  3. int i = 0; do { i++; } while (i < 0);
  4. for (int i = 0; i != 10; i += 3) { }
Show answer & solution

Answer: Options (B) and (C)

Detailed solution

Concept. A loop terminates when its condition eventually becomes false. For unsigned counters and for equality tests with a stride that does not divide the gap, the condition can be permanently true.

Step by step.

  1. (A) An unsigned int is never negative, so i >= 0 is always true. When i is 0 the decrement wraps to 4294967295 and the loop never ends.
  2. (B) i takes 0, 2, 4 and then 6, at which point 6 < 5 is false. It terminates.
  3. (C) The body runs once (i becomes 1) and then 1 < 0 is false. A do-while always executes its body at least once. It terminates.
  4. (D) i takes 0, 3, 6, 9, 12, … and never equals 10, so the test is never false. It does not terminate.

Final answer. Options (B) and (C)

Common trap. Option (A) is the trap: the loop looks exactly like a signed countdown that ends at 0, but on an unsigned type the final decrement wraps instead of going negative. Option (D) shows the second trap — != is safe only when the stride divides the target.

  4. (D) TRUE. For a zero size the call may return NULL or a unique pointer to no object; if a pointer is returned it must be freed and must not be dereferenced.

Answer: (A), (B) and (D).

Common misconception. Believing that realloc(p, 0) is a portable way to free memory. It is not; call free.

Takeaway. Free exactly what was allocated, exactly once, and set the handle to NULL afterwards.

DS-U2-Q17MCQmedium

A buffer allocated with malloc is grown by the statement below. If the reallocation fails, what is the defect?

p = realloc(p, 100 * sizeof *p);
  1. realloc returns NULL and p is overwritten, so the original block is leaked and its address is lost.
  2. There is none: realloc leaves p unchanged when it fails, so the old block is still reachable.
  3. It is a constraint violation that a conforming compiler must diagnose.
  4. It leaks memory even when the reallocation succeeds.
Show answer & solution

Answer: Option (A)

Detailed solution

Concept. realloc may move the block, so it returns the new address. On failure it returns NULL and leaves the original block allocated and unchanged. Assigning the result straight back to p therefore destroys the only handle to that block.

Step by step.

  1. Success: the new address is returned and the old block is released. Assigning to p is then correct.
  2. Failure: NULL is returned, and the old block is still allocated.
  3. Writing p = realloc(p, n) stores NULL into p, so the old address is lost and the block can never be freed — a leak.
  4. The safe pattern keeps the result in a temporary: q = realloc(p, n); if (q) p = q;

Answer: (A).

Common misconception. Believing that a failed realloc frees the old block. It does not; the caller still owns it.

Takeaway. Never overwrite the only pointer to a block with a value that may be NULL.

DS-U2-Q18MCQmedium

Consider the function below. Which statement correctly describes the pointer it returns?

int *make(void) { int x = 42; return &x; }
  1. It is valid: the lifetime of x extends to the end of the program because the pointer escapes the function.
  2. It is a compile-time error to return the address of an automatic variable, so the program cannot be built.
  3. It is undefined behaviour: the pointer refers to an object whose lifetime ended when make returned.
  4. It is valid, but the value read through the pointer is merely unspecified.
Show answer & solution

Answer: Option (C)

Detailed solution

Concept. x has automatic storage duration: its lifetime begins on entry to the block and ends when the block terminates. A pointer to it after that point is dangling.

Step by step.

  1. The object x ceases to exist when make returns.
  2. The returned address therefore refers to no object; the C standard makes any use of it undefined behaviour.
  3. Compilers usually diagnose it (-Wreturn-local-addr), but it is not a constraint violation, so a conforming implementation may accept the program.
  4. Undefined behaviour is stronger than "unspecified value": the program has no defined meaning at all, and the value may even appear to be 42 on some builds.

Answer: (C).

Common misconception. Calling the result "unspecified" or "garbage but harmless". Reading through a dangling pointer is undefined behaviour, not merely an unpredictable value.

Takeaway. Return a pointer to a static object, to a caller-supplied buffer, or to a heap block — never to an automatic local.

DS-U2-Q19NATmedium

How many bytes are leaked when the following function returns?

void f(void) { char *p = malloc(20); char *q = malloc(30); p = q; free(p); }
Show answer & solution

Answer: 20

Detailed solution

Concept. A block is reachable only through the pointers that hold its address. Overwriting the last such pointer loses the block permanently, and that is what "leaked" means.

Step by step.

  1. malloc(20) returns block A and stores its address in p.
  2. malloc(30) returns block B and stores its address in q.
  3. p = q overwrites the only handle to block A. Block A is still allocated but no longer reachable.
  4. free(p) frees block B, which is correct. Block A is never freed, so 20 bytes leak.

Answer: 20

Common misconception. Reporting 30, the size of the block that was freed, or 50, the total requested. A leak is measured by the block that became unreachable.

Takeaway. Free in the reverse order of allocation, and null a handle as soon as the block behind it is released.

DS-U2-Q20MCQeasy

What does the following program print?

#define SQR(x) x*x #include <stdio.h> int main(void) { printf("%d", SQR(2 + 3)); return 0; }
  1. 11
  2. 25
  3. 13
  4. 10
Show answer & solution

Answer: Option (A)

Detailed solution

Concept. The preprocessor performs textual substitution. SQR(x) x*x replaces the parameter by the argument tokens exactly as written, with no parentheses added.

Step by step.

  1. SQR(2 + 3) expands to 2 + 3*2 + 3.
  2. Multiplication binds tighter than addition, so the expression is 2 + 6 + 3.
  3. The value is 11, and it is printed as 11.
  4. Defining #define SQR(x) ((x)*(x)) would give ((2+3)*(2+3)) = 25.

Answer: 11 (option A).

Common misconception. Treating the macro as a function call and answering 25. A macro has no parameter objects; it has tokens.

Takeaway. Parenthesise every parameter and the whole body: #define SQR(x) ((x)*(x)).

DS-U2-Q21MSQmedium

Which of the following statements about the C preprocessor are TRUE?

  1. A macro name is replaced by the preprocessor before compilation, so the arguments of a function-like macro are not type-checked.
  2. #define MAX(a,b) ((a)>(b)?(a):(b)) evaluates each of its arguments exactly once.
  3. A macro may be redefined without error provided the new definition is identical to the previous one.
  4. #undef removes a macro definition, after which the identifier may be redefined.
Show answer & solution

Answer: Options (A), (C), (D)

Detailed solution

Concept. Macro expansion happens in translation phase 4, before any type information exists, and it is pure token substitution.

Step by step.

  1. (A) TRUE. The preprocessor knows nothing about types; the expanded text is type-checked only afterwards, as ordinary code.
  2. (B) FALSE. MAX(i++, j) expands to ((i++)>(j)?(i++):(j)), so the chosen argument is evaluated twice. This is the classic reason to prefer an inline function.
  3. (C) TRUE. An identical redefinition is permitted; a different one must be diagnosed.
  4. (D) TRUE. #undef ends the definition, and the name may then be defined again, possibly with a different body.

Answer: (A), (C) and (D).

Common misconception. Assuming a macro behaves like a function with arguments evaluated once, which silently breaks expressions with side effects.

Takeaway. Never pass an expression with a side effect to a macro parameter.

DS-U2-Q22MCQeasy

What does this program print?

#include <stdio.h> void f(void) { static int n; n++; printf("%d ", n); } int main(void) { f(); f(); f(); return 0; }
  1. 1 1 1
  2. 1 2 3
  3. 0 1 2
  4. 3 3 3
Show answer & solution

Answer: Option (B)

Detailed solution

Concept. static on a block-scope variable changes its storage duration, not its scope. The object has static storage duration: it is created and zero-initialised once, before the program starts, and lives for the whole run.

Step by step.

  1. n is zero-initialised a single time.
  2. First call: n becomes 1, prints 1.
  3. Second call: the same object is incremented to 2.
  4. Third call: 3. Output 1 2 3 .

Answer: 1 2 3 (option B).

Common misconception. Expecting 0 1 2 by treating the initialiser as running on every call, or 1 1 1 by forgetting that static gives the object a lifetime beyond the call.

Takeaway. static at block scope = one object, one initialisation, program lifetime, still invisible outside the block.

DS-U2-Q23NAThard

What integer does the following program print?

#define SQ(x) x * x #define CUBE(x) SQ(x) * x #include <stdio.h> int main(void) { printf("%d", CUBE(1 + 2)); return 0; }
Show answer & solution

Answer: 7

Detailed solution

Concept. Macro arguments are substituted as raw token sequences, and the result is then rescanned for further macros. With no parentheses anywhere, the surrounding operators re-associate the whole expression.

Step by step.

  1. CUBE(1 + 2) → SQ(1 + 2) * 1 + 2.
  2. The rescan expands SQ(1 + 2) → 1 + 2 * 1 + 2.
  3. The full expression is 1 + 2 * 1 + 2 * 1 + 2.
  4. Multiplication first: 1 + 2 + 2 + 2 = 7.

Answer: 7

Common misconception. Answering 27, the mathematical cube of 3, or 9 by expanding only the inner macro. Both assume the macros were parenthesised, and neither was.

Takeaway. Write #define SQ(x) ((x)*(x)) and #define CUBE(x) (SQ(x)*(x)); a macro is safe only when every argument and the whole body are parenthesised.

DS-U2-Q24MCQhard

What does this program print?

#include <stdio.h> int x = 10; int main(void) { int x = 20; { extern int x; printf("%d ", x); } printf("%d", x); return 0; }
  1. 10 20
  2. 20 20
  3. 10 10
  4. 20 10
Show answer & solution

Answer: Option (A)

Detailed solution

Concept. An extern declaration at block scope declares an identifier with external linkage; it does not introduce a new object, it names the one already defined at file scope.

Step by step.

  1. At file scope x is defined and initialised to 10, with external linkage.
  2. In main, the automatic int x = 20; hides the file-scope object inside the body of main.
  3. Inside the inner block, extern int x; declares x again with external linkage, so the name refers to the file-scope object: 10 is printed.
  4. After the block ends, the inner declaration goes out of scope and the automatic x = 20 is visible again. Output: 10 20.

Answer: 10 20 (option A).

Common misconception. Expecting 20 20, on the assumption that extern simply re-declares the nearest visible x. Linkage, not visibility, decides which object is named.

Takeaway. extern inside a block reaches outside the function; it is the one declaration that ignores shadowing.

DS-U2-Q25MSQmedium

Which of the following statements about scope, linkage and lifetime in C are TRUE?

  1. A block-scope variable declared static keeps its value between calls and is initialised only once.
  2. An object declared const has static storage duration by default.
  3. A file-scope variable declared static has internal linkage and is not visible from another translation unit.
  4. The lifetime of an automatic variable ends when its block terminates, and the storage it used may then be reused.
Show answer & solution

Answer: Options (A), (C), (D)

Detailed solution

Concept. C separates three ideas: scope (where a name is visible), linkage (whether another translation unit can refer to it) and storage duration (how long the object exists). static and const touch different ones.

Step by step.

  1. (A) TRUE. Block scope plus static storage duration: one object, initialised once, value preserved across calls.
  2. (B) FALSE. const qualifies the type, not the storage duration. A block-scope const object has automatic storage duration unless it is also declared static.
  3. (C) TRUE. At file scope, static gives internal linkage, so the name is private to that translation unit.
  4. (D) TRUE. Automatic storage duration ends at the closing brace; the memory may be reused, which is why a pointer to it becomes dangling.

Answer: (A), (C) and (D).

Common misconception. Conflating const with static. const says the object will not be modified; it says nothing about when the object exists.

Takeaway. Ask three separate questions of any declaration: where is the name visible, who can link to it, and how long does the object live.
