DS-U1-Q01MCQeasy

Compiled with a C99-or-later compiler on a machine where int is 32 bits, what does this program print?

#include <stdio.h> int main(void) { printf("%d %d\n", 7 / 2 * 2, -7 / 2); return 0; }
  1. 6 -3
  2. 7 -3
  3. 6 -4
  4. 7 -4
Show answer & solution

Answer: Option (A)

Detailed solution

Concept. In C99 and later, integer division truncates towards zero, so -7 / 2 is -3, not -4. Multiplication and division have equal precedence and associate left to right.

Step by step.

  1. 7 / 2 is integer division: both operands are int, so the result is 3.
  2. Then 3 * 2 gives 6 — the multiply happens after the division because of left-to-right associativity.
  3. -7 / 2 discards the fractional part towards zero: the exact quotient is -3.5, truncated to -3.

Final answer. 6 -3

Common trap. Python and many pocket calculators use floor division, where -7 / 2 is -4. C truncates towards zero, so the second value is -3. The first trap is reading 7 / 2 * 2 as 7 / (2 * 2) = 1 or as floating point 7.

DS-U1-Q02MCQeasy

On an implementation where sizeof(int) is 4, what is the value of sizeof('A') in C?

  1. 1
  2. 2
  3. 4
  4. It depends on the character encoding used by the compiler
Show answer & solution

Answer: Option (C)

Detailed solution

Concept. In C a character constant such as 'A' has type int, not char. Its size is therefore the size of an int.

Step by step.

  1. The literal 'A' is a character constant whose type is int (C11 §6.4.4.4).
  2. No conversion to char takes place inside sizeof, because the operand of sizeof is not evaluated or converted to a narrower type.
  3. Hence sizeof('A') == sizeof(int) == 4.

Final answer. 4

Common trap. This is the classic C-versus-C++ confusion: in C++ 'A' has type char and the answer would be 1. The character encoding never changes the size of an int.

DS-U1-Q03MCQeasy

What does this program print?

#include <stdio.h> int main(void) { int a = 6, b = 3; printf("%d\n", a ^ b | a & b); return 0; }
  1. 7
  2. 5
  3. 2
  4. 1
Show answer & solution

Answer: Option (A)

Detailed solution

Concept. Bitwise AND binds tighter than XOR, which binds tighter than OR, so the expression groups as (a ^ b) | (a & b).

Step by step.

  1. a & b with a = 6 (110₂) and b = 3 (011₂) gives 010₂ = 2.
  2. a ^ b gives 101₂ = 5.
  3. 5 | 2 gives 101₂ | 010₂ = 111₂ = 7.

Final answer. 7

Common trap. Reading the expression left to right and computing (6 ^ 3) | 6 first, or assuming all three bitwise operators share precedence. The precedence order is & above ^ above |. Option 5 comes from evaluating only a ^ b and stopping.

DS-U1-Q04MCQmedium

What does this program print, assuming CHAR_BIT == 8?

#include <stdio.h> int main(void) { unsigned char c = 250; c = c + 10; printf("%u\n", c); return 0; }
  1. 260
  2. 4
  3. 0
  4. 10
Show answer & solution

Answer: Option (B)

Detailed solution

Concept. Unsigned arithmetic is performed modulo 2ⁿ for an n-bit type. Assignment to an unsigned type reduces the value modulo 2ⁿ; it never traps and never wraps into a negative number.

Step by step.

  1. In c + 10 the unsigned char is promoted to int, so the sum is the ordinary integer 260.
  2. The assignment back to unsigned char converts the value modulo 2⁸ = 256: 260 mod 256 = 4.
  3. So c holds 4 and %u prints 4.

Final answer. 4

Common trap. Answering 260 ignores the conversion on assignment; answering 0 assumes the value wraps to a signed negative and is then read as unsigned. Neither happens — the reduction is modulo 256 and the result is 4.

DS-U1-Q05MSQmedium

Which of the following statements about the standard C integer types are TRUE?

  1. sizeof(short) <= sizeof(int) on every conforming implementation
  2. sizeof(char) is 1 on every conforming implementation
  3. Signed integer overflow is defined to wrap around, exactly as it does for unsigned types
  4. Plain char is signed on every conforming implementation
Show answer & solution

Answer: Options (A) and (B)

Detailed solution

Concept. The C standard fixes minimum ranges and a rank order for the integer types, but leaves the size of most of them to the implementation. It also leaves signed overflow undefined and the signedness of plain char implementation-defined.

Step by step.

  1. (A) is true: the standard requires sizeof(short) <= sizeof(int) <= sizeof(long), so a short can never be larger than an int.
  2. (B) is true: sizeof(char) == 1 by definition — a byte in C is exactly one char, whatever its bit width.
  3. (C) is false: unsigned arithmetic is defined modulo 2ⁿ, but signed overflow is undefined behaviour. An optimiser may assume it never happens.
  4. (D) is false: whether plain char behaves as signed char or unsigned char is implementation-defined; only signed char and unsigned char are distinct types with fixed signedness.

Final answer. Options (A) and (B)

Common trap. The tempting error is (C): students see unsigned wrap-around and assume signed types do the same. They do not — signed overflow is undefined, and a program that relies on it can behave differently at -O0 and -O2. Option (D) is the other classic: char is not guaranteed signed.

DS-U1-Q06MCQmedium

What does this program print?

#include <stdio.h> int main(void) { int x, y = 2; x = (y += 3, y * 2); printf("%d\n", x); return 0; }
  1. 5
  2. 10
  3. 8
  4. 2
Show answer & solution

Answer: Option (B)

Detailed solution

Concept. The comma operator evaluates its left operand, discards that value, then evaluates the right operand and yields its value. The parentheses make the whole comma expression the right-hand side of the assignment to x.

Step by step.

  1. The left operand y += 3 runs first: y becomes 2 + 3 = 5; its value 5 is discarded.
  2. The right operand y * 2 is then evaluated with the updated y: 5 * 2 = 10.
  3. The comma expression yields 10, which is assigned to x.

Final answer. 10

Common trap. Two traps. First, forgetting that the left operand has already changed y, so the second operand uses 5 rather than 2 — that gives the distractor 4 or 5. Second, reading the comma as a declaration separator; inside an expression it is the comma operator. Note also that int x, y = 2; initialises only y.

DS-U1-Q07NAThard

What does this program print?

#include <stdio.h> int main(void) { unsigned char c = 0xF0; int r = c << 4; printf("%d\n", r); return 0; }
Show answer & solution

Answer: 3840

Detailed solution

Concept. In a shift expression the operands are promoted to int first (the usual arithmetic conversions), so the left shift happens on a 32-bit value, not on an 8-bit one. The result of c << 4 is therefore not reduced modulo 256.

Step by step.

  1. c holds 0xF0 = 240.
  2. Integer promotion converts c to the int value 240 before the shift.
  3. 240 << 4 = 240 × 16 = 3840, which is 0xF00 and still fits in a 32-bit int.
  4. The assignment to r is a plain int assignment, so no truncation occurs and %d prints 3840.

Final answer. 3840

Common trap. The classic error is to keep the value 8 bits wide and answer 0: 0xF0 << 4 truncated to 8 bits is 0x00. That would be true only if the shift were performed in unsigned char arithmetic, which C does not do. Remember that shifts do not truncate to the left operand's type.

DS-U1-Q26MCQeasy

On an implementation where int is 4 bytes and float is 4 bytes, what is the value of sizeof(1.0f + 1)?

  1. 1
  2. 4
  3. 8
  4. It cannot be determined without knowing the value of 1.0f + 1.
Show answer & solution

Answer: Option (B)

Detailed solution

Concept. The type of an arithmetic expression is fixed by the usual arithmetic conversions, and sizeof reports the size of that type, not of a computed value.

Step by step.

  1. 1.0f has type float and 1 has type int.
  2. The usual arithmetic conversions convert the int operand to float, so the sum has type float.
  3. There is no double in the expression: a float stays float unless a double operand forces promotion.
  4. sizeof(float) is 4 on this implementation, so the value is 4.

Answer: Option (B)

Common misconception. Assuming that any floating-point expression is evaluated in double and answering 8. Only an unsuffixed literal such as 1.0 is a double; 1.0f is not. A second trap is thinking sizeof evaluates the operand — it does not, which is why the value of the sum is irrelevant.

DS-U1-Q27MCQeasy

What does this program print?

#include <stdio.h> int main(void) { int a = 017, b = 0x1F; printf("%d %d\n", a, b); return 0; }
  1. 15 31
  2. 17 31
  3. 15 1F
  4. 017 31
Show answer & solution

Answer: Option (A)

Detailed solution

Concept. The base of an integer literal is set by its prefix: a leading 0 means octal, 0x means hexadecimal, and no prefix means decimal.

Step by step.

  1. 017 is octal: 1·8 + 7 = 15.
  2. 0x1F is hexadecimal: 1·16 + 15 = 31.
  3. Both initialisers store the integer values 15 and 31; the base affects only how the source text is read.
  4. %d prints them in decimal, so the output is 15 31.

Answer: Option (A)

Common misconception. Reading 017 as the decimal seventeen. The second trap is expecting %d to echo the hexadecimal digits — to see 1f you must print with %x.

DS-U1-Q28MCQmedium

On a machine where int is 32 bits, what does this program print?

#include <stdio.h> int main(void) { int i = -1; unsigned int u = 1; printf("%d\n", i < u); return 0; }
  1. 1
  2. 0
  3. -1
  4. The behaviour is undefined
Show answer & solution

Answer: Option (B)

Detailed solution

Concept. When an int meets an unsigned int of the same rank, the usual arithmetic conversions turn the int into unsigned int before the comparison.

Step by step.

  1. The conversion of a negative value to unsigned is defined as arithmetic modulo 2³², so -1 becomes 4294967295u.
  2. The comparison is therefore 4294967295u < 1u, which is false.
  3. A relational operator yields int 0 or 1, so the value passed to %d is 0.
  4. Hence the program prints 0.

Answer: Option (B)

Common misconception. Reasoning in signed arithmetic, where −1 < 1 is true, and answering 1. This is the mirror image of the classic -1 < sizeof(x) trap: an unsigned operand in a mixed expression silently reinterprets the signed value.

DS-U1-Q29MCQmedium

What does this program print?

#include <stdio.h> int main(void) { int x = 1; x <<= 3; x |= 1; x ^= 5; printf("%d\n", x); return 0; }
  1. 8
  2. 9
  3. 12
  4. 13
Show answer & solution

Answer: Option (C)

Detailed solution

Concept. Compound assignment operators apply one bitwise operation at a time, in the order written, and each one assigns the result back to the variable.

Step by step.

  1. x = 1, i.e. binary 0001.
  2. x <<= 3 shifts left by three: 1000, so x = 8.
  3. x |= 1 sets the low bit: 1001, so x = 9.
  4. x ^= 5 is 1001 XOR 0101 = 1100, so x = 12.

Answer: Option (C)

Common misconception. Using | and ^ in the wrong order, or replacing the XOR by an OR, which gives 13. Bit 3 survives the OR and is cleared by the XOR because 5 has that bit set.

DS-U1-Q30MSQmedium

Which of the following statements about C integer and character constants are TRUE?

  1. The integer literal 10 has type int.
  2. The hexadecimal literal 0x1F has the decimal value 31.
  3. An integer literal that begins with 0 is octal, so 011 equals 9.
  4. A character constant such as 'a' has type char.
Show answer & solution

Answer: Options (A), (B) and (C)

Detailed solution

Concept. Literal type is determined by the literal's form and by the value it must hold; character constants are the one constant form whose type surprises most candidates.

Step by step.

  1. (A) An unsuffixed decimal literal whose value fits in int has type int. TRUE.
  2. (B) 0x1F = 1·16 + 15 = 31. TRUE.
  3. (C) A leading zero means octal, and 011 octal = 1·8 + 1 = 9. TRUE.
  4. (D) In C a character constant has type int, not char — which is why sizeof('a') equals sizeof(int). FALSE.

Answer: Options (A), (B) and (C)

Common misconception. Option (D) is the standard error, imported from C++, where character constants do have type char. In C the value of 'a' is an int holding the execution character set code.

DS-U1-Q31NATeasy

What does this program print?

#include <stdio.h> int main(void) { printf("%d\n", (5 > 3) + (2 == 2) + (1 != 1)); return 0; }
Show answer & solution

Answer: 2

Detailed solution

Concept. Relational and equality operators yield the int values 1 and 0, so their results can be added like any other integers.

Step by step.

  1. 5 > 3 is true, giving 1.
  2. 2 == 2 is true, giving 1.
  3. 1 != 1 is false, giving 0.
  4. The sum is 1 + 1 + 0 = 2.

Answer: 2

Common misconception. Believing comparison results cannot be used in arithmetic, or assuming they are of type _Bool and therefore print differently. In C the result of a comparison is a plain int.

DS-U1-Q32NAThard

On a machine where unsigned int is 32 bits, what does this program print?

#include <stdio.h> int main(void) { unsigned int a = 3000000000u; printf("%u\n", a * 2u); return 0; }
Show answer & solution

Answer: 1705032704

Detailed solution

Concept. Unsigned arithmetic is performed modulo 2ⁿ, so a result that overflows wraps around rather than invoking undefined behaviour.

Step by step.

  1. The exact product is 3000000000 × 2 = 6000000000.
  2. The modulus for 32-bit unsigned int is 2³² = 4294967296.
  3. 6000000000 − 4294967296 = 1705032704, which is still below the modulus, so one subtraction suffices.
  4. %u prints that wrapped value.

Answer: 1705032704

Common misconception. Answering 6000000000, or assuming the wrap-around is undefined behaviour. Wrapping is guaranteed for unsigned types only; the same computation on a signed int would indeed be undefined.

DS-U1-Q08MCQeasy

What does this program print? (It compiles; the compiler only warns.)

#include <stdio.h> int main(void) { int x = 0; if (x = 0) printf("A\n"); else printf("B\n"); return 0; }
  1. A
  2. B
  3. Nothing is printed
  4. It does not compile
Show answer & solution

Answer: Option (B)

Detailed solution

Concept. The condition of an if is any scalar expression; here it is an assignment expression, whose value is the value stored. Storing 0 makes the condition false.

Step by step.

  1. x = 0 assigns 0 to x and yields the value 0.
  2. A zero value is false, so the else branch runs.
  3. The program prints B.

Final answer. B

Common trap. Reading x = 0 as the comparison x == 0. That comparison would be true and print A. This is why good compilers warn about an assignment used as a condition. With x = 1 the program would print A.

DS-U1-Q09MCQmedium

What does this program print?

#include <stdio.h> int main(void) { int i, j; for (i = 0, j = 10; i < j; i++, j--) ; printf("%d %d\n", i, j); return 0; }
  1. 4 6
  2. 5 5
  3. 6 4
  4. 10 0
Show answer & solution

Answer: Option (B)

Detailed solution

Concept. A for header has three parts separated by semicolons: initialisation, condition and update. The update here is a single comma expression, so both i++ and j-- run at the end of every iteration.

Step by step.

  1. Start: i = 0, j = 10; condition 0 < 10 true.
  2. After each iteration both counters move: (1, 9), (2, 8), (3, 7), (4, 6).
  3. At (5, 5) the condition 5 < 5 is false, so the loop stops with i = 5 and j = 5.

Final answer. 5 5

Common trap. Stopping at 4 6 — that is the state at the start of the last successful iteration, not the state after the failing test. The update clause always runs before the condition is re-tested, so the counters meet at 5.

DS-U1-Q10NATeasy

What does this program print?

#include <stdio.h> int main(void) { int c = 0; for (int i = 0; i < 5; i++) for (int j = i; j < 5; j++) c++; printf("%d\n", c); return 0; }
Show answer & solution

Answer: 15

Detailed solution

Concept. The inner loop starts at j = i, so it runs 5 - i times for each value of i. The total is the sum of an arithmetic series.

Step by step.

  1. For i = 0, 1, 2, 3, 4 the inner loop runs 5, 4, 3, 2, 1 times.
  2. Total: 5 + 4 + 3 + 2 + 1 = 15.
  3. Equivalently n(n + 1)/2 with n = 5, i.e. the number of pairs (i, j) with 0 ≤ i ≤ j < 5.

Final answer. 15

Common trap. Assuming both loops always run 5 times and answering 25, or counting only the strictly upper-triangular pairs (10) by starting the inner loop at j = i + 1. The condition is j < 5 with j starting at i, so the diagonal is included.

DS-U1-Q11MCQmedium

What does this program print?

#include <stdio.h> int main(void) { int x = 2; switch (x) { case 1: printf("one"); case 2: printf("two"); case 3: printf("three"); break; default: printf("other"); } return 0; }
  1. two
  2. twothree
  3. onetwothree
  4. twoother
Show answer & solution

Answer: Option (B)

Detailed solution

Concept. A switch transfers control to the matching case label and then simply falls through the following statements until a break or the end of the block. Labels do not act as implicit exits.

Step by step.

  1. The controlling value is 2, so control jumps to case 2:.
  2. The statement printf("two") runs.
  3. There is no break after it, so execution continues into case 3: and prints three.
  4. The break after case 3: ends the switch, so the default is never reached.

Final answer. twothree

Common trap. Assuming each case is exclusive, as in an if-else chain, and answering two. Fall-through is the default in C; a break is required at the end of every case you want to end. Note also that the default is skipped here only because a break intervened.

DS-U1-Q12MSQmedium

On a typical 32-bit implementation, which of these loops TERMINATE?

  1. for (unsigned int i = 10; i >= 0; i--) { }
  2. int i = 0; while (i < 5) i += 2;
  3. int i = 0; do { i++; } while (i < 0);
  4. for (int i = 0; i != 10; i += 3) { }
Show answer & solution

Answer: Options (B) and (C)

Detailed solution

Concept. A loop terminates when its condition eventually becomes false. For unsigned counters and for equality tests with a stride that does not divide the gap, the condition can be permanently true.

Step by step.

  1. (A) An unsigned int is never negative, so i >= 0 is always true. When i is 0 the decrement wraps to 4294967295 and the loop never ends.
  2. (B) i takes 0, 2, 4 and then 6, at which point 6 < 5 is false. It terminates.
  3. (C) The body runs once (i becomes 1) and then 1 < 0 is false. A do-while always executes its body at least once. It terminates.
  4. (D) i takes 0, 3, 6, 9, 12, … and never equals 10, so the test is never false. It does not terminate.

Final answer. Options (B) and (C)

Common trap. Option (A) is the trap: the loop looks exactly like a signed countdown that ends at 0, but on an unsigned type the final decrement wraps instead of going negative. Option (D) shows the second trap — != is safe only when the stride divides the target.

DS-U1-Q13MCQhard

What does this program print?

#include <stdio.h> int main(void) { int s = 0; for (int i = 0; i < 5; i++) { switch (i) { case 0: continue; case 1: s += 1; case 2: s += 2; break; case 3: s += 4; default: s += 8; } s += 100; } printf("%d\n", s); return 0; }
  1. 425
  2. 325
  3. 417
  4. 405
Show answer & solution

Answer: Option (A)

Detailed solution

Concept. Inside a switch that is inside a loop, continue belongs to the loop: it abandons the rest of the switch and the rest of the loop body, and jumps to the loop's update step. Fall-through still applies between case labels.

  3. 25
  4. 8
Show answer & solution

Answer: Option (B)

Detailed solution

Concept. The counter is incremented once per call, in every frame, through a pointer shared by all of them. The answer is the total number of calls made by the recursion tree, not the value returned.

Step by step.

  1. Let C(n) be the number of calls made by f(n). One call happens at the top, plus the calls made by its two children.
  2. Base cases: C(0) = C(1) = 1. For n ≥ 2: C(n) = 1 + C(n − 1) + C(n − 2).
  3. Compute: C(2) = 1 + 1 + 1 = 3, C(3) = 1 + 3 + 1 = 5, C(4) = 1 + 5 + 3 = 9, C(5) = 1 + 9 + 5 = 15.
  4. So c ends at 15.

Final answer. 15

Common trap. Answering 8, the value f returns, instead of the count. Answering 9 is C(4), the count one level down. The recurrence C(n) = C(n−1) + C(n−2) + 1 is worth remembering: for n = 5 it gives 15, and in general it grows like the Fibonacci numbers — the reason naive recursion here is exponential.

DS-U1-Q45MCQeasy

What does this program print?

#include <stdio.h> int c = 0; int f(int n) { c++; if (n == 0) return 0; return f(n - 1); } int main(void) { f(4); printf("%d\n", c); return 0; }
  1. 4
  2. 5
  3. 6
  4. 1
Show answer & solution

Answer: Option (B)

Detailed solution

Concept. The call count of a linear recursion is the number of distinct arguments, and the base-case call is a call like any other.

Step by step.

  1. f is invoked with 4, then 3, 2, 1 and finally 0.
  2. Each invocation increments the global c before testing the base case.
  3. The call with n = 0 also increments c before returning.
  4. So c = 5 when control returns to main.

Answer: Option (B)

Common misconception. Answering 4 by counting only the non-base calls. If the increment had been placed after the base-case test, the answer would indeed be 4 — the position of the statement decides it.

DS-U1-Q46MCQeasy

What does this program print?

#include <stdio.h> void f(int n) { if (n == 0) return; printf("%d", n % 10); f(n / 10); } int main(void) { f(407); printf("\n"); return 0; }
  1. 407
  2. 704
  3. 74
  4. 47
Show answer & solution

Answer: Option (B)

Detailed solution

Concept. Work done before the recursive call happens on the way down the stack, so the digits appear in the reverse of the order in which they are peeled off.

Step by step.

  1. f(407) prints 407 % 10 = 7, then calls f(40).
  2. f(40) prints 0, then calls f(4).
  3. f(4) prints 4, then calls f(0), which returns immediately.
  4. The digits appear as 7, 0, 4 — the output is 704.

Answer: Option (B)

Common misconception. Answering 407 by assuming the digits are printed most-significant first. To get 407 the recursive call must come before the printf, so that printing happens while the stack unwinds.

DS-U1-Q47MSQmedium

Which of the following statements about recursion and the run-time stack in C are TRUE?

  1. Each active call of a function has its own copy of its automatic local variables.
  2. A static local variable inside a recursive function is re-initialised on every call.
  3. The C standard fixes a maximum recursion depth.
  4. A recursive function with no base case still compiles and links.
Show answer & solution

Answer: Options (A) and (D)

Detailed solution

Concept. Automatic storage is per activation, static storage is per program, and the depth limit is an implementation property of the stack rather than a language rule.

Step by step.

  1. (A) Each activation record holds fresh automatic locals, which is why one call cannot see another's n. TRUE.
  2. (B) A static local is initialised once, before the program starts, and shared by all activations. FALSE.
  3. (C) No limit is specified; exceeding the available stack causes a crash, but the number is not fixed by the standard. FALSE.
  4. (D) A missing base case is not a compile error — the function compiles, links and then fails to terminate. TRUE.

Answer: Options (A) and (D)

Common misconception. Option (C) is often marked true on the assumption that 'the standard must limit recursion somewhere'. It does not; that is why the same program can run on one machine and overflow on another with a smaller stack.

DS-U1-Q48MCQhard

What does this program print?

#include <stdio.h> int f(int n) { if (n == 0) return 0; if (n % 2) return n + f(n - 1); return f(n - 1); } int main(void) { printf("%d\n", f(7)); return 0; }
  1. 9
  2. 12
  3. 16
  4. 28
Show answer & solution

Answer: Option (C)

Detailed solution

Concept. The recurrence has two branches: an odd argument contributes its own value plus the result on n − 1, an even argument contributes only the result on n − 1.

Step by step.

  1. f(7) = 7 + f(6), and f(6) = f(5) because 6 is even.
  2. So f(5) = 5 + f(4) with f(4) = f(3), and f(3) = 3 + f(2) with f(2) = f(1).
  3. f(1) = 1 + f(0) = 1, giving f(2) = 1, f(3) = 4, f(5) = 9, f(7) = 16.
  4. In effect the sum is 7 + 5 + 3 + 1 = 16.

Answer: Option (C)

Common misconception. Answering 28 by summing 7 + 6 + … + 1, which ignores the even branch, or 12 by dropping one term. The even case adds nothing at all, so only the odd arguments survive.

DS-U1-Q49MCQeasy

What does this program print?

#include <stdio.h> int f(int n) { if (n == 0) return 0; return (n % 2) + f(n / 2); } int main(void) { printf("%d\n", f(100)); return 0; }
  1. 2
  2. 3
  3. 4
  4. 7
Show answer & solution

Answer: Option (B)

Detailed solution

Concept. Dividing by 2 strips one binary digit per call, and n % 2 is the digit removed, so the recursion counts the 1-bits.

Step by step.

  1. 100 in binary is 1100100, which has three 1-bits.
  2. The first call adds 100 % 2 = 0 and recurses on 50.
  3. The chain continues 100 → 50 → 25 → 12 → 6 → 3 → 1 → 0, adding the low bit at each step.
  4. The bits added are 0, 0, 1, 0, 0, 1, 1 — a total of 3.

Answer: Option (B)

Common misconception. Answering 7 by counting the number of bits of 100 instead of the number of 1-bits, or 2 by miscounting the binary expansion. Writing 100 = 64 + 32 + 4 makes the three set bits visible immediately.

DS-U1-Q50NAThard

During the execution of this program, what is the maximum number of activation records of f that are alive at the same time?

#include <stdio.h> int f(int n) { if (n <= 1) return 1; return f(n / 2) + f(n / 2); } int main(void) { f(16); return 0; }
Show answer & solution

Answer: 5

Detailed solution

Concept. The number of live frames is the depth of the recursion, not the number of calls: the second recursive call starts only after the first has returned and its frame has been destroyed.

Step by step.

  1. The chain of nested calls is f(16) → f(8) → f(4) → f(2) → f(1).
  2. Each of those five calls is still on the stack when f(1) is entered, so the depth is 5.
  3. The second f(n / 2) in each frame runs after the first has returned, reusing that depth rather than adding to it.
  4. The total number of calls is 31, but the maximum number of live frames is 5.

Answer: 5

Common misconception. Answering 31 by counting calls instead of depth, or 4 by forgetting that the base-case call f(1) is itself a live frame. Depth is the longest root-to-leaf chain, not the size of the tree.
